# Web 专题看板与双范围聊天原型验证

日期：2026-10-11。范围：[本地原型](../design/web-prototype.html)，非生产 Web 工程、Go 业务或真实 pi 验收。用户明确要求继续开发后，当前 Agent 按 [限定计划](../superpowers/plans/2026-10-11-web-kanban-prototype.md) 串行实现。

## 实际交付

- 桌面为左侧功能专题看板、右侧聊天，无第三常驻面板；专题可增删，删除后全部任务转入不可删除的“其他”。
- 任务创建后为未开始；五态角标与专题归属独立，演示状态控件明确标为模拟。普通聊天不会启动任务或接受结果。
- 无卡片选中为项目对话，选卡片为对应任务对话；各自有稳定 Conversation ID、独立历史、草稿和阅读位置。模拟 pi 标识不代表进程存在。
- 模拟发送捕获原会话、文本和草稿版本；迟到接受／回复不会清其他范围草稿或抢回选择，同范围新草稿也保留。删除专题不丢会话。
- 窄屏切换看板／聊天，360px 按专题查看单列；离线禁写、保留草稿与已捕获回调。所有隐藏范围的未发送草稿都会触发浏览器离开提示，刷新后重置。
- [桌面截图](../design/web-desktop.png) 1440×1100、[手机截图](../design/web-mobile.png) 360×900 已生成并人工查看。旧截图另存，历史 20 项测试未计入本批。

## RED、修复与独立验收

1. 状态测试先因模块不存在失败，再新增纯状态模块通过；浏览器在旧 HTML 上加载成功、因缺少看板／项目对话失败，再替换布局通过。部分附加 UI 检查在实现后补充，没有逐项观察 RED，不声称完全逐行为 TDD。
2. 独立只读审查 Agent `kanban_review` 首轮实际重跑 15 项状态测试和当时 34 项浏览器检查，并额外构造手机反例：A 阅读位置 300、B 500，经看板互选后 A 错误恢复为 500。评级为 1 Important、1 Minor，无 Critical。
3. 已增加手机 A/B 反例并观察失败，再修复隐藏面板不保存零值、返回看板前保存、目标聊天显示后恢复。同一审查 Agent 重跑 15＋43 项通过，独立原反例也确认 A 恢复 300、B 恢复 500，Important 消失。
4. 驱动问题单独处理：Esc 等待排队的 close／焦点事件；原生 Enter 发送文本才能触发浏览器默认点击；截图刷新接受原型的未保存草稿警告并等待页面 load，避免重载时使用已销毁的执行上下文。这些不是产品能力或额外业务测试。
5. 第二轮审查又发现重复点击当前“聊天”标签会恢复旧阅读位置的 Minor。新增第 44 条断言观察 RED，改为已在聊天视图时直接返回后 GREEN；主 Agent 重跑 15＋44 项通过，同一审查 Agent 再跑 44 项通过，无新增 Important。

最终独立验收：**0 Critical、0 Important、1 Minor**。审查者实际重跑状态测试、浏览器测试及自行构造的手机反例；没有修改代码，也没有测试真实后端。复验截图在 `/tmp/kaiwu-kanban-review-final2`，交付截图使用主 Agent 最终运行的成果。

Minor 暂留：看板整体重建时，键盘选择卡片后的焦点可能落回 body；手机创建任务后原触发点隐藏，焦点恢复尚不完善。原生 Enter 可选择卡片、弹窗 Esc 回到可用触发点的场景已测，不能代表完整无障碍验收。
