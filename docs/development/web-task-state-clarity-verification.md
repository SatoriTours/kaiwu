# 任务状态与详情可读性修正（2026-10-14）

用户反馈：列表“需要确认”、详情“已中断”，找不到确认入口；手机详情被空进度卡挤占，无法看见有用信息。本批属于已批准任务流程的纠错，沿用 Go／Vue／SQLite／独立 pi／worktree／WebSocket；不新增依赖、真实模型调用或 Git 提交。

## 根因与修正

只读核对实际数据：任务 `needs_confirmation`，执行和会话均 `interrupted`，没有轮次报告或完整结果摘要；已有一条部分助手回复和 10 条工具记录，其中一条未返回。之前中断和恢复代码把这些情况统一改为“需要确认”，前端又以不同字段分别判定列表与详情。无报告的旧任务只显示空成果占位，恢复按钮在消息列表末尾，手机消息区域太小。

- 执行中断持久化为 `interrupted`，服务启动规范化旧记录；列表和详情共用 `taskState` 判定。恢复 CLI 只恢复连接，保持上次执行未完成，不重发指令或虚构完成结果；恢复后提示发送“继续开发”。
- 已完成结果与会话连接独立：正常结束的待确认结果不会因空闲会话丢失、重启或恢复失败变成失败；无需启动模型即可确认已保存结果。旧版无 Round 的已完成执行必须有 `awaiting_review` 和完成时间，以精确版本令牌确认；中断／运行中／旧轮次不能确认。确认仍不提交或合并 Git。
- 恢复／确认操作移至进度卡上方首屏。详情先显示原始要求、AI 摘要或真实最近回复、已返回／未结束工具数、实际 Git 待提交文件数；没有结构化报告时不再显示虚构的方案阶段和“开始后才有进展”。方案、成果、验证、记录通过“查看方案、成果与记录”展开，实际文件路径可核对。
- 手机默认收起详细报告，保留摘要和最多两项成果，展开后可读取报告内容；聊天头收紧，会话 ID 放入提示，任务详情移除重复运行状态说明。聊天的“上次执行中断／回复中断”不再写成“结果待确认”。历史摘要按下一轮起点截断，查看完整回复跳到对应消息。
