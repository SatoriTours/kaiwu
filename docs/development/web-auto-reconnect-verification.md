# 会话自动接回（2026-10-15）

用户针对“执行已中断／恢复原会话”要求“自动处理就好”。本批将手动恢复前置步骤并入现有发送／继续开发流程；不新增后台恢复队列、模型总结调用、依赖或服务，不提交／合并／推送 Git。

## 实际行为

- 会话中断或失败后，用户直接发送新消息即可：保存新的操作与轮次，Go 检查原会话文件／身份、工作区与写入锁，启动或接回原 pi 上下文后只发送这条新消息。
- 中断卡片显示继续开发图标；点击或发送“开始开发”，继续同一 execution／会话／worktree，保留原分支、工具记录和配置。不为继续中断任务创建另一套执行记录或工作区。
- 去掉常规页面“恢复原会话”按钮和发送前的恢复限制；中断提示说明直接发消息或点继续即可自动接回。已有完成结果仍可确认，继续修改直接编辑／发送。
- 没有新用户意图就保持中断记录：切卡片、刷新、断开浏览器、服务重启均不触发模型调用，不自动补发上次指令。消息结果未知仍通过原 operationId 查回执，不把传输重连当作再执行指令。旧 `resume` API 保留兼容。
- 原会话丢失／损坏、身份不符、未回收写入者或正在 Git 合并仍阻止启动，错误和草稿／历史保留，不悄悄创建替代上下文。

## 验证过程

先观察 RED：workbench 的新 send/start 意图仍被“请先明确恢复”拒绝；Manager 新消息恢复原上下文失败；真实 Go＋主动退出假 pi 的浏览器场景仍出现恢复按钮。随后实现，针对性验证 GREEN。

- workbench／agent 全量回归通过。
- 前端状态测试 11/11、类型检查和生产构建通过。
- 独立浏览器场景通过：假 pi 异常退出两次，分别直接发送新要求和点击继续图标；会话 ID／文件、execution ID、工作区不变，新消息只出现一次，中断指令不重发，没有发送 resume 命令。
- 完整 Go race 通过；审查修正后 agent/workbench race 和全模块 vet 再次通过。Chromium 最终 24/24 通过（32.8 秒）。
- 旧手机固定数据场景调整为自动接回说明、无需恢复按钮、直接发送可用，仍核对要求／最近回复／工具及 Git 信息和聊天空间。

没有加载个人扩展、发送真实模型请求或执行真实项目的继续开发。实际服务已更新至 `server/bin/kaiwu-server-auto-reconnect`，沿用原 7331；更新前活动会话／合并均为 0，SQLite 备份完成，旧令牌／Cookie／项目／消息／工作区保留。

## 授权与限制

本次“自动处理”的具体触发已在实施前说明：新消息／明确继续操作时自动接回，并非后台无条件重复运行未完成指令。恢复失败需要处理明确原因后再次发送，不无限自动重试有副作用操作。团队协作与通用编排仍是未来方向。


## 独立审查

单个新上下文 reviewer 只读审查，发现 1 Important（旧版恢复留下的 awaiting_review＋无完成时间被误当成可确认状态，图标派生状态与点击条件不一致）、1 Minor（已完成／接回失败提示提供不存在入口或承诺必然成功）。两项均修复：统一规范化无完成证据的旧记录，继续保留原 execution 和工具；列表／详情／App 启动按同一派生状态，旧记录后端也可继续；根据实际入口和失败情况显示“尝试接回”。补充旧记录 RED→GREEN 回归，未称开发者复验为独立复审。

实际 7331 的手机只读烟测通过：旧登录恢复、手动恢复按钮消失、卡片／聊天继续开发图标可用、中断时填写新消息后发送按钮可用，原消息完全保留，0 页面错误；只填写草稿，没有发送 commands 或模型请求。临时烟测 Cookie 文件已删除。
