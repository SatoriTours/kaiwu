# 任务开始开发与紧凑界面验证（2026-10-12）

用户批准 [任务启动方案](../superpowers/specs/2026-10-12-task-start-design.md)，并补充要求全页更简洁、控件更小。本批按 [实施计划](../superpowers/plans/2026-10-12-task-start.md) 在用户指定目录串行实现；根仓库仍无提交，不创建基线提交、不推送。

## 实际改动

- 卡片与选中任务聊天提供“开始开发”；任务聊天独立发送该短句（允许首尾空白、末尾句号／感叹号）进入同一 `start_task`。项目范围提示先选任务，否定句继续作为普通讨论。
- 同一任务保留原 pi session ID／文件／配置和上下文。空闲只读进程可靠关闭、消费协程排空后，才在任务 worktree 启用写入与命令工具；选择卡片不启动／停止进程。
- SQLite 保存执行阶段、工作区、基线、配置、工具记录与摘要。回执幂等、忙碌状态防重、共享 8 个会话预算；轮次结束是“需要确认”，无验证命令则提示“未执行验证”。
- 有提交从固定 SHA 创建 worktree，已跟踪的脏改动拒绝首次开始；空仓库使用 orphan worktree，复制 Git 列出的未忽略普通输入（含暂存文件），排除常见凭据、私有目录与不安全链接。不自动提交、合并、推送、重置或清理结果。
- Linux 独立进程组在 leader 仍可核实、尚未 reap 时回收同组子进程，避免 PID 复用误杀。其他系统编译保留，只读可用，执行明确拒绝。
- 任务 OS 锁和持久进程组归属阻止跨服务宿主双写；强杀后必须确认旧组不存在活动进程才能恢复，归属未知则拒绝，不根据保存 PID 自动 kill。未派发指令与可能已发送区分，恢复不重发。
- 48px 顶栏、23px 品牌图标、15px 品牌文字、28px 顶栏控件；统一轻量专题背景、卡片、按钮及对话排版。保持桌面左看板／右聊天和手机切换。

## 独立审查与修正

独立只读审查发现 2 项 Important，暂无 Critical／Minor；未修改代码、调用模型或操作预览服务。两项均先复现失败，再在一次修复中通过回归及 Go 全量／race：

1. 强杀宿主后旧工具进程可能仍写入，而新 Manager 可恢复另一个执行者。`TestRecoveryRefusesOrphanedWriterAfterHostKill` 实际强杀隔离宿主并保留写入子进程，修复后拒绝恢复；旧进程明确退出后可恢复原身份且不重发。另验证未知启动窗口拒绝执行。
2. 首次启动已保存但未调度时，重启误把未发送消息当作不确定历史，导致原 session 无文件而永久无法恢复。`TestNeverDispatchedStartRecoversWithoutReplaying` 修复后保存 `not_sent`，恢复同一 session ID、不派发旧指令，随后可明确重新开始。
