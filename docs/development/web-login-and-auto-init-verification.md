# Web 登录保留与自动 Git 初始化修正

日期：2026-10-12。用户要求刷新后无需重复输入密钥，并明确给目录后应自动初始化 Git。

定位结果：

- 登录 Cookie 原有 12 小时有效期，但对应凭证仅存在 Go 进程内存；服务更新重启后失效。
- 用户截图为旧版表单，新服务却要求请求带 `initializeGit`。实测正在运行的服务器与当前构建资源一致；截图所在旧表单的具体加载／缓存过程无法从截图确定。

修改：

- 登录使用 30 天持久 Cookie，HttpOnly、SameSite Strict；SQLite 保存随机登录凭证散列、访问令牌散列和期限，未保存原始访问令牌。刷新、重新打开浏览器和服务重启可恢复登录；退出撤销凭证，更换访问令牌或到期则失效。
- `login_sessions` 表通过兼容的追加建表加入现有 SQLite，项目状态与操作记录格式不变，认证更新不改变看板 revision。
- 添加项目不再要求勾选，保存时自动创建不存在的目录、初始化未建仓库的目录。已有仓库和文件保留。兼容旧表单只发送名称／路径；远程地址继续可选，不提交、克隆、推送。
- 旧内存登录会话无法跨升级保留，更新后需重新输入一次令牌，此后使用持久凭证。

实际验证：

- 先观察 HTTP 回归失败：仅名称／路径被要求勾选，登录在数据库／handler 重启后返回 401；修正后通过。
- Go 测试覆盖服务重启、持续期限、篡改 Cookie、退出后重启仍撤销、访问令牌变化、到期，以及普通／新目录自动初始化与现有数据保留。
- `go test ./...` 通过，`webapi`／`workbench` race 通过，`go vet ./...` 和 Go 构建通过，修改包 gofmt 无输出。
- 前端 4 项状态检查和 Chromium 9 项场景通过；包含刷新、用已存 Cookie 新开浏览器上下文、退出撤销与无勾选框新建 Git 项目。Vue 类型检查与 Vite 生产构建通过。
- 实际后台服务更新到 `http://192.168.2.122:7331`。Chromium 在此地址登录后，页面刷新、真实进程重启、再次刷新均无需输入令牌；新表单及 360px 无横向溢出检查通过。

验证仅使用临时项目／隔离假 pi；实际预览只登录、打开／关闭表单与重启服务，没有替用户创建项目或调用真实模型。
