# 添加项目与 Git 初始化验证

日期：2026-10-11。用户反馈添加项目不应要求预先初始化 Git，并询问远程地址入口。

后续修正：2026-10-12 用户明确要求直接自动初始化，已移除勾选要求并兼容旧表单，见 [修正验证](web-login-and-auto-init-verification.md)。下面保留首轮实现记录。

本批修改：

- 添加项目表单支持服务器绝对目录；默认勾选未建仓库时创建目录并初始化 Git。已有文件保留，已有仓库不重新初始化。
- Git 远程地址可选，HTTPS／SSH 地址仅配置 `origin`；留空沿用已有配置，不覆盖不同的 origin，不克隆／提交／推送，不调用模型。
- Go 命令在操作标识、版本、名称、重复项目与数量校验后才准备目录；已成功操作重放回执，不重复修改 Git 配置。
- 目录与 SQLite 无跨资源事务；初始化后若保存失败，目录和仓库保留，供检查后重试，服务不自动清理。

实际验证：

- Go HTTP 回归使用真实临时 Git 仓库：已有普通目录／不存在目录、文件保留、无远程地址、SSH origin、不同 origin 冲突保护、回执重放以及无效请求不创建目录。先观察新字段被旧接口拒绝，再实现并通过。
- 新浏览器回归先观察旧页面缺少初始化选项，再实现并通过。全套 Chromium 8 项场景通过，前端状态检查 4 项通过；假 pi，无真实模型调用。
- Vue 类型检查与 Vite 生产构建通过；`go test ./...`、修改包 `webapi`／`workbench` 的 race、`go vet ./...`、Go 构建通过；修改包 gofmt 检查无输出。
- 后台服务已更新，沿用 `192.168.2.122:7331`、原数据目录与令牌。实际 LAN URL 的 Chromium 登录、新表单、360px 无横向溢出验证通过；只打开表单，未替用户创建项目或初始化截图中的目录。

本批不包含远程仓库克隆、创建远程托管仓库、已有项目远程设置页或任务执行闭环。当前填远程地址仅关联 origin；留空可独立使用本地 Git。
