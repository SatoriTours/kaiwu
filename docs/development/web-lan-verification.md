# 指定私网地址访问验证

2026-10-11 用户明确要求“我要局域网能访问的 ip”，取代上一批仅回环预览的运行限制。本机路由确认局域网接口地址为 192.168.2.122。

小范围调整：KAIWU_LISTEN_ADDR 可指定私网 IP，但必须加载有效令牌工作台配置；默认回环行为不变，未认证私网、通配地址和公网地址仍拒绝。继续保留 Host／Origin／Cookie／CSRF 检查，没有开放 CORS或调用模型。普通私网 HTTP 的浏览器没有 crypto.randomUUID，因此操作标识改用 crypto.getRandomValues 的128位随机值，不使用弱随机。

实际验证：

- 新配置用例先 RED（私网被拒绝），修改后配置／启动／app 回归及完整 Go test ./... 通过。
- 新无 randomUUID 的状态测试先 RED，修改后前端状态4/4、vue-tsc 和 Vite 生产构建通过。
- 后台真实服务绑定 192.168.2.122:7331，healthz 200。复用原私有数据和登录令牌，后台进程与当前工具连接分离；原预览进程已停止或确认不存在。
- Chromium 从真实私网 URL 打开并登录成功、收到 WebSocket revision；浏览器实际 isSecureContext=false 且 randomUUID=undefined，仍成功生成32位十六进制 operationId。创建验证请求在浏览器中拦截，不写入测试项目或调用模型，运行时错误为空。

目前仅在服务机器通过其私网地址验证，未从第二台设备实测，不代表路由器／防火墙／设备间隔离配置的结论。当前是令牌保护的局域网 HTTP，TLS／公网部署不在本批范围。后台服务按用户要求保留运行；PID／日志／令牌文件都在被忽略的 .kaiwu 私有目录，没有 Git 提交或推送。
