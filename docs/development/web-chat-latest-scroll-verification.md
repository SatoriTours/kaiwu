# 聊天打开时定位最新消息

日期：2026-10-17。用户确认：每次打开、刷新或切回项目／任务对话时自动滚到最新消息；停留期间手动上翻不被新消息打断，回到底部后继续跟随。桌面与手机一致。本批不改变消息历史、草稿、会话身份或 Agent 生命周期。

## 原因与实现

- 原先保存／恢复每个会话的 `scrollTop`，缺省位置为 0，且滚动监听未立即执行，首次挂载已有长历史时停在顶部。
- 原监听返回新数组 `[conversation.id, visible]`；不可变快照替换 conversation 时，即使两项值未变也会触发回调。改为两个独立监听源，普通消息更新不再误触发打开定位。
- `ChatPanel.vue` 在首次挂载、会话 ID 变化、手机聊天重新可见时，等待 Vue DOM 更新后滚至消息区域底部；监听失效／组件卸载时取消过期定位。
- 消息增长仅在更新前已位于底部时跟随，允许不足 2px 的小数舍入误差；不沿用原 60px 阈值，避免轻微上翻也被拉回。
- 删除 `App.vue`、`workbench.ts` 中旧阅读位置状态、传参与保存逻辑。各会话草稿隔离不变。旧文档中的恢复阅读位置是历史行为，由本次决定取代。

## 实际验证

- 将原“恢复阅读位置”浏览器用例替换为新规则的回归。80 条合成历史同时用于首次 HTTP 快照与 WebSocket 快照；增量事件只注入隔离测试浏览器，不改服务器消息、不启动模型。
- 旧实现失败：首次进入距离底部 16007px。初次修复中，普通消息更新仍误触发定位；独立监听源修正后通过。
- 新增轻微上翻检查：原 60px 阈值在上翻 30px 后仍拉回底部，回归失败；收紧到底部舍入容差后通过。
- 最终覆盖：首次挂载已有历史、刷新、项目／任务切换、上翻 30px、阅读较早历史时的增量回复、返回底部后流式跟随、390px 手机看板／聊天切换、聊天隐藏期间新消息及手机刷新。
- 提交前导出暂存快照复验时，两个既有预览用例（`a real task HTTP preview is isolated, remains after acceptance, and stops explicitly`、`late preview responses stay with their original task and absent previews do not start a model`）曾因会话启动容量不足失败。滚动用例额外创建项目会影响其他用例对默认项目的选择，增加驻留会话。已将滚动用例改为优先复用套件的原会话，只有独立运行时才创建必需数据；不放宽产品的 8 会话限制。
- `npm --prefix apps/web run build`：类型检查、Vite 与 Go embed 复制通过。
- `npm --prefix apps/web test`：16/16 通过。
- `npm --prefix apps/web run test:browser`：32/32 通过。
- `GOTOOLCHAIN=local go -C server test ./...`、Go 服务二进制构建及 `git diff --check`：通过。本批未另跑完整 race／vet、非 Chromium 浏览器或原生端。
