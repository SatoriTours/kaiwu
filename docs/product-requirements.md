# 项目背景与需求

状态：**已确认产品决定的整理，不是已批准的完整实现规格。**

## 1. 起点与理念

用户希望打造自己真正使用的开源 AI 开发平台，统一接入不同 Coding Agent，并通过主 Agent 协调开发工作。最初参考了聊天、任务看板和多种 Agent 的展示形式，功能有些类似 Paseo，但不照搬为全部首版范围。

产品首先服务用户本人及个人开发者，优先做好日常开发体验，而不是先建设团队平台或通用工作流产品。

中文名 **开悟**，英文 **kaiwu**（小写）。品牌内核是「从想法到作品」：产品是个人认知的投射，创造过程也让人深化、更新自己的认知。「让认知，成为作品」曾作为品牌文案建议，尚未正式确定为口号。

## 2. 当前阶段的成功方向

当前优先先把 **pi 接入做精**，而非同时接入很多 Agent。原来讨论的 pi + Codex 调整为 pi 先行、Codex 后续，不代表永久取消多 Agent 接入。

用户已确认第一条闭环采用 **pi 主 Agent＋pi 执行 Agent**：

1. 用户选择项目和一套配置方案，提出需求。
2. 主 Agent 分析、拆解、派发并跟踪。
3. 执行 Agent 在隔离 worktree 中完成实际修改。
4. 执行构建/测试，准确回报成功、失败、阻塞或取消。
5. 主 Agent 汇总实际改动、验证证据和未解决事项，回到原对话。
6. 合并主分支、推送、破坏性清理由用户确认。

这是已认可的验收方向；API、页面、权限细节、测试样例与实现方案尚待设计，不能保证任意任务都能自动成功。

## 3. 平台与技术决定

| 部分 | 已确认要求 | 尚待设计 |
| --- | --- | --- |
| PC | Nim + 用户开发的 Leaf；Windows、macOS、Linux 均是首版目标 | 最低系统版本、CPU 架构、SDK 版本、网络到 UI 的接入与原生验收 |
| Android | Kotlin 原生 Android + KMP + Compose Multiplatform；SQLite、App 自动更新 | 共享代码边界、数据库访问库、最低系统版本、签名与更新渠道 |
| Web | 2026-10-11 用户确认新增，作为主要开发入口，优先完整流程；PC/Android 首版目标保留 | 页面与交互提案见 [Web 设计](superpowers/specs/2026-10-11-web-workbench-design.md)，Vue 3＋TypeScript＋Vite、SQLite、本机令牌与首次发送启动／重启显式恢复已确认 |
| 服务端 | 自有后端全部使用 Go + net/http + chi + coder/websocket；开发时在本机运行，不新增其他语言宿主或 pi 扩展 | 正式运行系统、版本、模块组织、持久化、业务 API、部署 |
| Agent | pi 优先；主 Agent、执行 Agent 可以配置；Codex 后续扩展 | 完整能力矩阵、角色字段、适配兼容策略 |

历史上服务端曾讨论 Nim；用户已经明确改为 Go，并进一步要求自有后端全部使用 Go。PC 仍用 Nim，不设计 Go/Nim 双服务或 TypeScript/Node SDK 宿主，不新增自有 pi 扩展。pi 本身作为第三方 CLI 子进程运行，其所需运行时不等于用其他语言开发开悟后端。未来编排工具桥优先研究 Go MCP 服务，具体方案另行审核，不自动纳入本批次。

## 4. 多端功能边界

Web、PC、Android 围绕同一任务流程设计。Web 是已确认的主要开发入口，优先打磨完整流程；原生端继续保留。以下是共同功能方向，Web 看板、首批服务及显式任务启动已获批实现，其余自动编排／审批能力仍为后续提案：

- 选择项目和整套配置方案。
- 提交需求、与主 Agent 对话。
- 查看任务、进度、执行摘要和待处理事项。
- 处理人工确认，切换当前 Agent 支持的模型。
- 查看改动/验证的文字摘要。

**首版明确不做**：源码浏览、diff 展示、代码编辑器、完整 IDE。

交互终端没有被批准为首版必需项。日志和摘要不应扩展为代码浏览器。

### 已确认的主界面与聊天范围

用户明确纠正主界面方向：**Kanban 看板是主要页面，右侧常驻聊天窗口**，不是对话居中、执行详情居右的布局。

- 最新纠正：看板的竖列是**功能专题**，不是任务状态；用户可以手动添加、删除专题列。此决定取代此前固定三列的说法。
- 增加“其他”专题作为收纳列；删除有任务的专题时，该专题所有任务移到“其他”，不随列删除。
- 每张卡片是一个任务，右上角角标区分：未开始、执行中、有结果需要确认、执行完成可查看结果、执行失败、已中断；中断必须提供恢复入口，不能当作已完成结果待确认。
- 状态变化更新卡片角标，不因为执行状态改变而移动专题归属；“执行完成可查看结果”不自动等于用户已验收。
- 未选中任何任务卡片：右侧显示整个项目的对话。
- 选中某张卡片：右侧显示该卡片对应任务的对话。
- 项目级与任务级是明确的聊天范围，不能把发送目标混淆。
- 用户进一步确认：项目聊天和每张卡片的任务聊天，背后各自绑定独立的代码 CLI 会话；目前均为独立 pi 会话。项目会话负责项目级沟通与创建／协调任务，卡片会话负责对应任务沟通。切卡片切换聊天目标，各会话历史与模型上下文独立；首次发送启动、切卡片不停、重启显式恢复已确认；首批上限 8 个驻留会话，不自动空闲回收。

专题归属与任务状态是两个独立维度。用户已确认删除专题时任务移到“其他”；操作只改变分组，不改变任务状态、聊天归属或结果，不授权删除任务、停止执行或删除 worktree。卡片选择、草稿与历史规则见 [Web 设计](superpowers/specs/2026-10-11-web-workbench-design.md)。用户要求继续开发后，已按 [限定交互原型计划](superpowers/plans/2026-10-11-web-kanban-prototype.md) 实现本地专题看板与双范围聊天；保底列保护、表单限制、草稿／异步隔离和窄屏规则已有模拟验证，见 [本批记录](development/web-kanban-prototype-verification.md)。正式首批已实现 Go API、Vue 工程、SQLite、令牌、事件和 pi RPC 生命周期，已新增卡片／聊天“开始开发”、原会话上下文切入独立 worktree、结果待确认和紧凑简洁样式；隔离假 pi／Git 验证见 [任务启动记录](development/web-task-start-verification.md)，真实模型与自动编排尚未验收。详见 [服务验证](development/web-service-verification.md)。

### 卡片 worktree 与主分支集成（2026-10-12 已确认并实现）

每张开发卡片使用独立 worktree。项目自动识别并记住默认主分支，新项目为 main，无必填分支选择；高级设置可覆盖本地目标和提交身份。新任务基线取主分支，已有任务不重建。执行角标与 Git 状态独立：未开始、无改动、待提交、未合并、已合并、需核查；按钮、pi 或外部 Git 操作均按实际修改和提交可达关系重新检查。

卡片／任务聊天顶部合并图标，或单独发送“合并到主分支”“提交并合并到主分支”，打开同一审核框。用户确认具体范围后，服务提交未提交修改并普通合并，优先快进；保留任务分支、目录与原 pi 上下文。冲突、脏主目录、异常归属、私密文件等明确阻止；不自动 stash／reset／强行合并／推送。断线不终止服务器操作，重启只核查不重放。详见 [设计](superpowers/specs/2026-10-12-task-merge-design.md) 与 [实际验证](development/web-task-merge-verification.md)。

### 任务成果与效果验收（2026-10-17）

用户反馈原“确认结果”缺少预览与点击反馈，并在评审设计后明确要求实现。现改为开发结束“待验收”→查看效果／运行结果→确认完成；完成反馈持续保留，后续可继续修改或审核合并。网页任务只有用户明确启动且服务器核验真实进程／HTTP 后才显示可用预览，无配置时显示已有成果与输出，不自动调用模型补充。桌面效果在看板位置、右侧原任务聊天保留；手机效果视图提供返回入口。原型与正式服务区分、限制与验收见[验证记录](development/web-task-result-preview-verification.md)。

## 5. 配置与模型规则

- 面向用户的 Agent 回复须使用系统界面语言；当前 Web 固定简体中文，正文、过程更新、结果摘要和结构化报告的自然语言内容均用简体中文，代码／命令／协议字段与枚举值保持原样。2026-10-16 已补充 pi 系统指令并更新 7331，真实模型输出尚未验证。
- 启动任务时选择一套已配置方案，不要求逐个选择 Agent/模型。
- 保存任务配置快照，修改方案模板不追溯已有任务。
- 任务内切换模型仅影响当前任务，不自动回写模板。
- 主 Agent、执行 Agent 的类型/模型由配置控制；pi 优先阶段不等于永久固定类型。
- 运行中无需支持更换 Agent 类型或 pi↔Codex 上下文交接。
- 可以切换该 Agent 实际支持的模型，**下一轮调用生效，当前请求不中断**。
- 模型列表和能力必须来自实际 Agent；不能承诺任意模型/provider 都能在同一会话安全切换。

模板字段、思考级别、提示词、权限、角色种类与保存交互尚需设计。准确生效边界和每轮实际模型记录需要适配测试。

## 6. 执行、权限与联网

已确认：

- 首版单执行节点：Go 服务、Agent、项目代码/worktree 同机。该机器可以是开发电脑或远程开发机器。
- 独立 Git 开发任务使用独立 worktree；同工作区单写入者，由主 Agent 协调。
- 执行 Agent 必须回报实际修改和测试结果；合并、推送、破坏性清理需用户确认。
- Web/PC/Android 经局域网或用户已有 VPN 直连；远程必须认证。Web 同机可从 Go 服务页面入口访问，同源静态托管已实现，按用户要求当前在指定私网 IP＋固定 7331 端口提供令牌认证访问。
- 首版不自建公网中继、云账号系统或多执行节点中心调度。

建议方向，详细规则待定：

- 服务端负责任务/Agent 生命周期；客户端断网或关闭不自动终止任务。
- 重连恢复进度；服务异常与恢复失败清晰可见，不能偷偷重跑有副作用操作。
- 开发服务默认回环地址；真机联调可设计 ADB reverse 或经批准的局域网访问。

尚需确认或验收：配对／TLS、通用工具授权、工作区回收及跨平台进程树／真实模型能力。当前 Web 登录、事件重连、Linux 写入者保护、自动 Git 初始化和卡片审核提交／合并已有实现与限定验证。
