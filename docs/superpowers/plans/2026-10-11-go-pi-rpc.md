# Go pi RPC 基础 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 用户执行方式和 Paseo 编排规则优先；不自动提交。

**Goal:** 用纯 Go 实现受控 RPC 子进程、可靠 JSONL、请求关联、有界事件与故障回收，并用隔离 Go 假进程验证。

**Architecture:** `server/internal/pirpc/` 是具体 pi RPC 包，不新增适配平台。独立协议、缓冲和进程单元由 Client 组装；进程、任务所有者与单次调用 context 分离。现有 HTTP 入口不启动 pi。

**Tech Stack:** Go 1.25.0 基线、标准库 `os/exec`、`os.Pipe`、`encoding/json`、`context`、`sync`、`log/slog`；无新增依赖或其他语言测试工程。

**Spec:** [Go pi RPC 基础规格](../specs/2026-10-11-go-pi-rpc-design.md)。用户在审核请求后回复“继续”，批准规格并进入计划阶段；不是批准本计划或编码。

**执行状态：** 用户回复“ok”，批准本计划及当前会话串行编码＋完成后独立只读验收；Tasks 1–5 已完成；本机与独立验收通过，首轮 2 Important/1 Minor 已修正复验。进度与裁定见 [ledger](../../development/go-pi-rpc-ledger.md)。不启动真实 pi/模型，不提交。

## Global Constraints

- 自有后端及新增测试全部 Go；pi 是第三方 CLI，不新增自有 TypeScript 扩展、SDK 宿主、MCP 服务或客户端工程。
- module 保持 `github.com/SatoriTours/kaiwu/server`、`go 1.25.0`、chi v5.2.3；不新增 module、go.work 或依赖。
- 协议样本为 pi 1.0.4，不声称完成真实版本联调；测试不依赖 pi/Node 安装、个人配置或真实凭据。
- 启动必须使用绝对 Program/Dir、参数数组、非 nil Env；不隐式继承环境、不拼 shell、不搜索 PATH。
- 默认值：MaxRecordBytes=4MiB，MaxPending=32，MaxWriteBytes=16MiB，MaxEvents=128，MaxEventBytes=16MiB，StderrTailBytes=64KiB。
- 默认等待：StartupTimeout=8s，CallTimeout=30s，WriteTimeout=2s（单记录开始写入后的总期限），ShutdownTimeout=5s，DrainTimeout=1s。
- Options 中零值采用默认值、正值覆盖、负值拒绝；不新增环境配置项。raw 预算不含终止 LF/可选 CR，不等于整个 Go 堆的绝对上限。
- 取消单次 Call/NextEvent 不取消生命周期；可能已发送的请求结果未知，不自动重发、abort 或重启。
- 事件满则可观测地失败并清理直接子进程；客户端断线不能拥有本 Client 的 lifetime context 或内部消费循环。
- stdout 只按 LF 分帧，接受 EOF 的完整末 JSON 对象；污染、截断或坏 envelope 不静默忽略。
- 普通日志和默认错误字符串不含参数、环境、原始 stdout/stderr、远端 error 或秘密；仅显式内部诊断可获取原始数据。
- 不绑定 HTTP/任务/存储/UI，不把 response、agent_end、agent_settled 当任务验收，不承诺后代进程树或沙箱。
- 所有 Go 命令使用 `GOTOOLCHAIN=local GOFLAGS=-mod=readonly`；现有非稳定本机工具链不替代稳定或跨平台验收。
- main 无基线提交；不为创建 worktree 提交。确认单写入者后串行编码，停止写入后只读审查；不提交/合并/推送/发布/清理已有成果。

公开类型固定如下，方法实现分别归相应任务，不一次预建空实现：

```go
type LaunchSpec struct { Program string; Args []string; Dir string; Env []string }
type Options struct {
    MaxRecordBytes, MaxPending, MaxWriteBytes int
    MaxEvents, MaxEventBytes, StderrTailBytes int
    StartupTimeout, CallTimeout, WriteTimeout time.Duration
    ShutdownTimeout, DrainTimeout time.Duration
    Logger *slog.Logger
}
type Command struct { Type string; Params json.RawMessage }
type Response struct {
    ID, Command string
    Success bool
    Data json.RawMessage
    ErrorText string
    Raw json.RawMessage
}
type Event struct { Type string; Raw json.RawMessage }
type Delivery uint8 // NotSent, Uncertain, Acknowledged，按此顺序从 0 开始
type Error struct { Code ErrorCode; Delivery Delivery; cause error }
type ErrorCode string
type ExitResult struct {
    PID int
    ExitCode *int // nil 表示无法取得退出码；不能用 0 冒充已退出
    Forced, Reaped bool
    Cause, CleanupError error
}
type Stats struct { IgnoredResponses uint64 }

func Start(lifetimeCtx context.Context, launch LaunchSpec, opts Options) (*Client, error)
func (c *Client) Call(ctx context.Context, cmd Command) (Response, error)
func (c *Client) NextEvent(ctx context.Context) (Event, error)
func (c *Client) Close(ctx context.Context) error
func (c *Client) Wait(ctx context.Context) (ExitResult, error)
func (c *Client) Diagnostics() []byte
func (c *Client) Stats() Stats
```

- `Wait` 的 error 仅表示调用者未等到收尾（如其 context 取消），不停止进程；完成时返回 result,nil，必须检查 Cause/CleanupError/Reaped。`Close` 启动唯一后台清理后等待，完成时返回 Cause 与 CleanupError 的组合；其 context 只限制等待。
- `Start` 的正常失败返回 nil,error，错误包括可检查的清理失败。若无法确认子进程回收，则保留并返回不可用、stopping 的 Client 与错误；Call 必须拒绝，所有者仍能 Close/Wait，不能丢失句柄假装清理完成。
- nil context 是非法输入；nil Logger 不记录日志，不使用个人默认 logger。输入 Args/Env 在启动前复制；Params 在 Call 期间由调用方保持不变，入队后 Client 只持有独立编码字节；返回 raw/诊断数据拥有独立内存，不复用读缓冲。
- ErrorCode 固定为 `invalid_input`、`protocol`、`record_too_large`、`too_many_requests`、`write_queue_full`、`event_overflow`、`remote_rejected`、`closed`、`process_exit`、`io`、`write_timeout`、`drain_timeout`、`shutdown_timeout`、`cleanup`、`canceled`、`deadline`、`id_exhausted`。暴露对应 `ErrInvalidInput`、`ErrProtocol`、`ErrRecordTooLarge`、`ErrTooManyRequests`、`ErrWriteQueueFull`、`ErrEventOverflow`、`ErrRemoteRejected`、`ErrClosed`、`ErrProcessExit`、`ErrIO`、`ErrWriteTimeout`、`ErrDrainTimeout`、`ErrShutdownTimeout`、`ErrCleanup`、`ErrCanceled`、`ErrDeadline`、`ErrIDExhausted` 的 sentinel；Error 实现 Error/Is/Unwrap，默认字符串由固定 Code 生成，不拼 cause 原文；Unwrap 允许内部显式检查根因，context sentinel 通过 errors.Is 保留。
- 响应已在 registry 确认后，取消/退出不能覆盖它；尚未确认时由 mutex 下的状态转换决定唯一结果，不能靠 select 随机选择两个已就绪分支。
