## 本批范围与已确认规则

- 列是功能专题，可手动添加／删除；不是“待办／进行中／已完成”状态列。
- 每张卡片是一个任务，右上角角标显示 **未开始、执行中、需要确认、执行完成可查看结果、执行失败** 五种状态；状态变化不改变专题归属。
- 增加“其他”专题；删除一个专题时，其所有任务转入“其他”，只改变分组，不删任务、不停执行、不改任务对话、草稿或结果，也不删 worktree。
- 未选卡片显示项目对话；选卡片显示该任务对话。不同范围不能串消息。
- 用户进一步确认：项目对话与每张任务卡片背后分别绑定独立的代码 CLI 会话，当前均为独立 pi 会话；切卡片切换聊天所连接的会话，消息与模型上下文按会话隔离。首次启动、空闲回收与恢复策略另行设计，本批模拟原型不启动真实 CLI。
- 本批制作模拟原型，验证专题管理、卡片角标、选择／返回、独立历史／草稿和迟到回复隔离；不连接现有 Go 服务或 pi，不发送真实请求，不执行 Git。
- “其他”作为保底列不可删除、显式返回项目按钮、窄屏两视图等规则已在原型实现和验证；这不是生产业务协议冻结。
- 下文真实项目、审批、模型、认证、持久化等属于后续产品提案。生产前端选型仍待确认，原型不需先安装 Vue／Vite。
- §12 链接当前原型及新检查；此前 20 项检查与旧截图单独保留，不复用为本批验收。

## 1. 产品定位与体验目标

Web 是个人开发者日常提出需求、与主 Agent 协作、观察执行、作出决定和验收成果的主要入口。浏览器连接自己的执行机器；项目、代码、pi 和 worktree 都在该机器上。用户无需把代码上传到开悟云端。

用户的主要操作是：**在看板上观察／选择任务，在右侧对整个项目或指定任务提出需求、沟通和处理结果。** 打开工作台时先看到看板与项目对话，而不是进入一张任务的聊天详情页。看板回答“现在在做什么、哪里需要我、结果是否有证据”，不以 Agent 数量、日志行数或不可验证的完成百分比作为进度。

核心闭环：选择项目与整套配置 → 提出需求 → 主 Agent 分析/派发 → 执行 Agent 在 worktree 开发 → 查看验证证据 → 用户验收 → 按授权处理 Git 操作。浏览器关闭、刷新、休眠不决定任务是否继续。

首版保持个人、单执行节点、pi 优先。支持桌面浏览器完整操作及手机浏览器的响应式访问；移动 Web 不替代 Android 原生端。

## 2. 首版功能范围

| 能力 | 首版行为 | 明确边界 |
| --- | --- | --- |
| 进入工作台 | 从 Go 服务提供的同源地址进入；完成身份验证并恢复上次项目 | 不做云账号、公网中继或多节点控制台 |
| 项目管理 | 登记服务器上的 Git 目录、校验可用性、选择项目、查看任务 | 浏览器文件上传不是添加服务器项目；不浏览源码 |
| 配置方案 | 创建/编辑整套主 Agent＋执行 Agent 配置；启动时选择并冻结快照 | 不要求每次创建任务逐个配置 Agent；凭据只保存服务器引用 |
| 需求与对话 | 未选卡片连接项目独立 pi 会话，选中卡片连接任务独立 pi 会话；新建需求、补充需求、下一轮消息排队 | 切换聊天目标不取消其他会话执行；启动／回收策略另行设计；不承诺打断、插队或撤回 |
| 任务与执行 | 查看阶段、阻塞、执行 Agent、工作区、验证摘要、事件时间线 | 执行详情只读；用户通过主对话协调，不绕过主 Agent 操作执行者 |
| 人工确认 | 查看具体动作、目标、影响与有效期，允许一次或拒绝 | 不提供笼统的永久全部允许；无可信执行边界时不开放真实危险动作 |
| 任务内模型 | 查询实际可用模型，按主/执行角色调整下一轮模型 | 不换 Agent 类型，不中断当前请求，不改模板；未验证能力不开放 |
| 结果验收 | 查看改动摘要、验证记录、限制；接受结果或继续修改 | Agent 结束不是任务已验收；接受结果不是 Git 授权 |
| 历史与恢复 | 查看历史、筛选、深链接、重连补发、显式恢复失败 | 不因刷新自动重跑；不承诺首版能恢复所有中断的进程 |
| 设置与诊断 | 连接、服务/客户端版本、能力状态、设备会话与脱敏诊断 | 不把完整 stderr、会话日志、密钥当普通产品内容展示 |

源码/diff 展示、代码编辑器、交互终端、可视化工作流编辑器、多人共享、Codex、云同步、离线执行均不纳入首版。

## 3. 信息架构与对象关系

```text
执行机器（一个服务实例）
  ├─ 项目（服务器 Git 路径）
  │   ├─ 项目对话（整个项目的需求、讨论及任务关联摘要）
  │   ├─ 功能专题（用户分组＋保底“其他”，不是执行状态）
  │   └─ 开发任务（看板上一张卡片，以稳定专题 ID 分组）
  │       ├─ 任务对话、主 Agent 会话、配置快照
  │       ├─ 执行子任务 → 执行 Agent → worktree/写入锁
  │       ├─ 待确认事项、验证记录、结果版本
  │       └─ 产品事件与审计记录
  ├─ 配置方案模板（可供不同项目复用）
  └─ 设备/浏览器会话
```

一张看板卡片对应一个完整开发任务，不对应一次模型调用或一个执行 Agent。执行子任务在卡片摘要／详情中呈现，不自动扩展成更多同级卡片。一个任务可以多轮修订，保留任务对话；验收后再修改生成新结果修订，不覆盖旧结论。

项目对话与各任务对话各有逻辑 Conversation，历史和消息所属范围分开。项目对话可以讨论目标、安排任务、展示带任务链接的进展摘要；任务对话聚焦该任务的需求、执行与验收。项目摘要不能冒充任务原始消息，也不自动把整个项目聊天注入每个任务的模型上下文。

用户已确认 Conversation 与 CLI 会话的关系：项目对话绑定一个独立 pi 会话；每张任务卡片的任务对话绑定各自独立 pi 会话。Go 服务维护 Conversation ID 到实际 pi 会话及运行实例的绑定，用户选择卡片时切换消息与事件所连接的目标。各会话的历史、模型上下文和运行状态分别管理；切换聊天目标不终止其他会话，也不把其他会话的历史自动拼入当前上下文。

独立会话不要求所有 pi 进程永久常驻。首次启动、并发运行实例管理、空闲回收、恢复原会话、配置快照及权限绑定需后续 Go 业务规格明确；不能每次点卡片都重新创建会话。本 UI 设计不授权项目级 Agent 直接写共享 checkout，任务内派发执行 Agent 的机制仍单独保留。

建议路由（接口尚未冻结）：

| 页面／状态 | 路径 | 内容 |
| --- | --- | --- |
| 入口 | `/` | 已有最近项目时进入其看板；首次为空时引导添加项目 |
| 项目看板 | `/projects/:projectId` | 看板＋右侧项目对话，没有选中卡片 |
| 选中任务 | `/projects/:projectId/tasks/:taskId` | 同一个看板页面，选中卡片＋右侧任务对话，不跳成独立聊天主页面 |
| 待处理 | `/inbox` | 可选跨项目聚合；点击事项回到对应看板并选中任务 |
| 配置 | `/profiles` | 方案列表、编辑、能力校验、模板版本 |
| 设置 | `/settings` | 服务连接、设备会话、外观、诊断 |

选中任务时保留看板筛选、列内滚动位置和当前项目。筛选不显示已选任务时，右侧仍保留该任务并提示“当前筛选未显示”，不得暗中改发送目标。卡片移列或被归档也不能让聊天跳到别的任务。确已删除／无权访问时保留范围说明并禁发，用户显式返回项目；初次打开失效深链接时显示错误，不自动替用户发送到项目。

深链接只负责定位，不授予权限。未认证先验证后回原位置；任务、审批及执行详情均验证项目归属与权限。

## 4. 主工作台布局

### 4.1 看板为主，右侧是聊天

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 开悟  项目：kaiwu ▾   配置 ▾   搜索／筛选   ＋任务   连接状态   设置    │
├──────────────────────────────────────────────┬─────────────────────────────┤
│               Kanban 任务看板                │ 项目对话 · kaiwu            │
│   连接恢复    │   项目体验   │     其他      │ 或：任务 #12 · 优化恢复      │
│               │              │              │ [返回项目对话]              │
│ 卡片 [执行中] │ 卡片 [确认]  │ 卡片 [未开始] ├─────────────────────────────┤
│               │              │              │ 当前范围的历史、Agent 回复  │
│               │              │              │ 问题／审批／结果关联卡片    │
│               │              │              │                             │
│               │              │              ├─────────────────────────────┤
│               │              │              │ 给当前项目／任务的消息……    │
│               │              │              │ 发送／排入下一轮 →          │
└──────────────────────────────────────────────┴─────────────────────────────┘
```

桌面建议右侧默认约 380–420px、至少约 360px，看板占其余主要区域；不再增加常驻执行详情第三栏。列多时在看板自身水平滚动，各列与聊天的垂直滚动独立，聊天不跟随看板横移。执行摘要／结果通过聊天内卡片或按需详情层查看，关闭详情回到同一个看板和聊天。

窄屏建议低于 1024px 使用“看板／聊天”两视图保持同一选中范围：初次显示看板，点击任务切到其聊天；回看板不清除任务选择，只有“返回项目对话”明确取消选择。1024px 及以上保留双栏；360px 看板按单列切换专题，不要求所有专题挤在一屏；专题切换不改变当前任务聊天。宽屏常驻右侧聊天是核心，具体断点须实际验证，不以文档证明布局已可用。

### 4.2 选择与返回的方案比较

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| A：点击卡片选中，右侧显式“返回项目对话”（推荐） | 范围清楚，点击空白／重复点卡片不会误切换；易做键盘操作 | 多一个可见返回动作 |
| B：再点卡片／看板空白取消选择 | 操作短 | 点空白滚动或重复点击可能意外切换发送目标 |
| C：右侧另设项目／任务标签页 | 有明显入口 | 标签、卡片与聊天三处选择可能不一致，增加首版状态 |

提案采用 A。选中卡片有边框和文字状态，聊天标题与输入框同时显示任务标识；按“返回项目对话”清除选择，恢复项目历史与草稿。重复点同一张卡片保持选中。卡片上的审批／详情等子动作不要触发第二次选择或意外发送；处理动作本身仍绑定精确任务 ID，不靠当前聊天推断对象。

### 4.3 功能专题管理

列代表功能专题，名称由用户填写，数量不固定。原型示例“连接恢复”“项目体验”“其他”仅为假数据，不是内建三列。专题与任务都使用稳定 ID，不能把显示名称用作对话或事件路由键。

“＋专题”添加空列；非空名称去首尾空白，原型限制 40 个 Unicode 码点，并拒绝同名专题，避免误选。新列追加在“其他”之前。空列显示“暂无任务”与新建入口，不自动生成任务。

普通专题提供删除动作：确认面板显示专题名和任务数量，明确“任务将移到其他，不会停止执行或删除任务”。取消不改数据；确认后一次性转移全部任务再移除专题，不出现丢卡片／无归属的中间状态。空专题也可删除。

**原型提案：保留不可删除的“其他”默认收纳列。** 无指定专题的新任务归入其他；若创建表单打开后所选专题已被删除，提交时归入其他并提示，不丢输入。删除专题不是删除任务、聊天、结果、执行进程或 worktree 的授权。选中任务因删除专题移列时，选中标识、聊天、历史、草稿和结果仍绑定原 taskId。

本批不做专题重命名、拖拽排序、手动移卡片、跨项目分组或归档自动化；这些可在明确需求后补充，不用拖拽改变真实执行状态。

### 4.4 任务卡片与五种角标

| 角标 | 含义 |
| --- | --- |
| 未开始 | 任务已建立，尚未执行 |
| 执行中 | 执行正在进行 |
| 需要确认 | 有信息或动作等待用户确认；具体问题在任务聊天中呈现 |
| 执行完成可查看结果 | 已有执行结果可查看，不自动等于用户验收，更不等于 Git 已提交／合并／推送 |
| 执行失败 | 显示失败原因和已有成果，不冒充完成 |

角标位于卡片右上角，同时有可读文字与区分性图标／颜色；不能只靠颜色或悬停识别。长标题留出角标空间，不覆盖任务号、摘要和选择入口。每个任务仍只有一张卡片，状态改变只更新角标、摘要和相应结果，不搬到别的专题。

卡片主要显示短标题／任务号、角标、最近活动及必要的摘要；执行 Agent 数量、验证和 Git 状态按需查看。未知进度不显示百分比。原型提供明确标为“演示状态”的五态切换，不假装服务器真的执行或验收。

五态是用户要求的卡片表达，不是对现有 pi 事件的直接映射，也不冻结生产 Task enum。部分执行受阻但其他仍继续时，提示需要确认且保留具体执行信息；原型不模拟生产调度。停止中／已停止／中断等精细生命周期需在 Go 业务规格里定义，不能为了五个角标丢弃事实或把停止标成完成。

## 5. 关键流程与交互

### 5.1 首次进入与添加项目

1. 同机访问服务地址；远程访问先满足认证及安全传输条件，具体配对方案另审。
2. 首次空白页展示“添加你的第一个项目”，说明目录位于执行机器，不是浏览器设备。
3. 输入服务器 Git 路径，服务验证路径、权限、仓库、基线与写入占用。项目名可编辑。
4. 无 Git、无提交、无写权限、目录不存在分别说明原因。空仓库可登记，但禁止创建 worktree 执行任务；不暗中创建提交。
5. 选择/创建配置方案，确认 pi 安装与凭据引用可用。检测缺失只展示修复步骤，不自动安装或调用模型。

首版可先用手动输入路径；服务器目录选择器不是闭环必需项。已有项目变脏不一概阻止登记，创建任务前显示工作区策略与冲突；不得替用户清理修改。

### 5.2 新建任务

看板工具栏“＋任务”打开轻量表单（移动端独立视图）：当前项目、所属专题（默认其他）、整套配置、需求、可选标题。默认配置可复用最近选择但需可见；不能仅因用户在项目对话输入一段文字就暗中开始多个执行任务。

建议区分“创建任务（未开始）”和“创建并开始”：前者建立卡片、不启动 Agent/worktree；后者先验证服务、Git 基线和配置，说明将创建隔离工作区。建立时保存配置快照，启动时重新校验，不追溯模板变化。项目对话提出的任务建议可以带明确的创建动作，执行前使用同样的服务校验和幂等规则。

服务器确认后卡片进入看板，显式创建动作可选中该新卡片并进入任务对话，项目原草稿保留。重复点击禁用；响应丢失显示“创建结果待确认”，使用原幂等键查询，不另建任务。服务尚未确认的临时卡片必须有“提交中／结果未知”标识，不能冒充已有任务。失败保留输入并指出具体原因。

标题可概括，不额外调用命名模型。空仓库允许组织未开始任务和讨论，开始需要 worktree 的执行则因无基线禁用；不自动创建提交。

### 5.3 右侧对话、草稿与异步切换

**默认范围：** 进入项目看板且无任务深链接时显示项目对话；点击卡片显示该任务对话；“返回项目对话”恢复项目范围。切换只改变展示和下一条消息的目标，不停止旧范围执行，也不立即发消息。

**历史与草稿：** 各 Conversation 独立保存消息历史、当前草稿和滚动位置。项目草稿不会带到任务输入框，任务 A 草稿不会带到任务 B；切回恢复原文。服务端负责实际聊天记录，浏览器仅维护草稿／有限已加载窗口，不把隐藏范围的整段历史拼到当前对话。

**加载与失效：** 切到 B 时立即更新标题和发送范围、显示 B 的加载状态，不能在 B 标题下暂时显示 A 的消息。Conversation ID 未确认前禁发；B 加载失败仅显示 B 的错误，不退回 A 或项目来“继续发送”。异步加载 A 的迟到结果写回 A 的缓存，不覆盖已显示的 B。

**发送归属：** 点击发送时捕获 Conversation ID、projectId、scopeType、taskId（任务范围必填）、消息与幂等键；之后即使切卡片，返回结果／流式事件仍归原范围。异步成功只能清除原范围对应版本的已发送草稿，不清掉切到 B 后新输入的文字；原范围失败保留原草稿，并给原卡片未读／错误提示。模型输出流不会把 UI 重新拉回该卡片。

**显示与通知：** 未选中范围的回复更新对应任务未读标记／项目通知，不混进当前聊天。项目对话可出现带任务号和链接的汇总卡片；这是明确的汇总内容，不是自动复制任务聊天。已读标记须实际看见相关消息后更新，不因单纯点卡片就全清。各范围滚动位置独立；上翻后不抢滚动，提示新内容。

**发送操作：** 建议 Enter 换行、Ctrl/Cmd+Enter 提交、移动端显式发送；中文组合输入不提交，空输入禁发。空闲为“发送”，运行中为“排入下一轮”，范围明确写“发送至项目 kaiwu”或“发送至任务 #12”。排队只追加，不承诺打断、编辑／撤回已接受消息；区分服务器接受、待调用、实际处理。

**执行内容：** 任务对话呈现需求、任务主 Agent 回复、子执行摘要、待确认和结果。执行详情按需打开，不增加常驻第三栏，不把右侧切成直接与执行 Agent 对话；用户仍通过对应协调会话沟通。项目聊天处不展示未验证的“停止全部／切所有模型”捷径，任务操作绑定具体 taskId。

**长任务不中断：** 切卡片、返回项目、切项目或关页面不取消已接受的消息／执行。会话加载、事件订阅与 Agent 生命周期由不同对象管理，不能关闭前端范围订阅就杀进程。停止始终是单独、有范围和确认的操作。

### 5.4 处理人工确认

待处理筛选／可选聚合页包含三类事项：回答问题、允许具体操作、验收结果。看板卡片、工具栏和对应任务聊天显示同一服务状态。项目范围可以展示带任务链接的汇总，点击后选中正确任务；操作始终绑定事项所属任务而非点击时的聊天范围。不因为弹窗关闭就认为事项已处理。

操作审批卡必须包括：操作类别、发起角色、原因、项目/工作区、精确目标、影响范围、适用结果或提交版本、有效期。Git 例子要展示源/目标分支、提交集合摘要、预期远端与当前头；需要提交、合并、推送时分别取得对应授权，不能将“继续”解析成所有 Git 操作获准。

允许按钮写“允许本次提交/合并/推送”，拒绝按钮保留“拒绝”，可附原因。高影响操作用详情确认面板；用户已明确授权且仍匹配范围的操作不重复审批。拒绝只拒绝该动作，主 Agent 可以解释或调整，不默认取消整个任务。

服务器以版本和动作范围原子校验。两个标签页/设备同时处理时，后到者显示“已在其他设备处理”；已过期或目标状态改变则标记失效，必须重新生成审批。提交响应未知时先查询结果，禁止猜测或无限自动重发。

**审批 UI 的前置条件**是服务拥有真实可信的执行边界；只在网页弹卡片却允许 pi bash 绕过，不满足上线要求。未具备时，首版可以提供说明及外部手动操作记录，但不能提供有执行含义的按钮或声称操作已受控。

### 5.5 调整当前任务模型

选中任务后的聊天标题／按需详情中选择该任务主 Agent 或具体执行 Agent，面板始终显示任务号。项目对话里的模型设置不能暗中覆盖所有任务；项目级会话的配置字段与启动策略待独立业务规格确认，本提案不提供跨范围批量切换。模型列表由实际适配器返回，不写死 provider 或跨 provider 兼容承诺；暂不可用项给出原因。

空闲时请求并等待服务确认；运行中显示“当前调用：A；下一轮：B（待生效）”。调度器需在下一轮模型调用边界应用设置，包括 Agent 内部连续调用；不能把一次用户消息简单当作一个模型调用。能力未验证前禁用运行时切换，并说明原因。

失败保留原有效设置，明确待生效设置是否被撤销；每次实际调用记录实际模型。任务创建快照保持不变，覆盖记录另存，不回写模板；以后新建执行 Agent 是否继承覆盖需要明确选择，首版建议不追溯、不自动继承。

### 5.6 停止、失败与重试

选中运行中的任务时提供“停止任务”，确认面板写明任务号，说明将取消未开始工作并请求运行中 Agent 停止，已产生修改保留。消息送出后再切到其他卡片不能改变原停止目标，项目范围不提供含义模糊的全局停止按钮。操作请求后先显示“停止请求已提交／结果待确认”；服务确认正在取消时显示“停止中”，只有进程与写入者确实停止才显示“已停止”。若仍可能有残留进程，显示“停止未完成”，禁止释放工作区写入锁并启动新写入者。

首版不提供含义模糊的“暂停”。暂时停止不意味着可以无损恢复任意会话。失败状态显示失败阶段、可保留成果、诊断摘要与可选下一步；“继续处理”先检查运行状态和现存工作区，创建有来源记录的新尝试，不默认从头重跑命令。

### 5.7 查看结果与验收

任务聊天内展示结果摘要卡片，按需打开“结果详情”：需求及完成情况、改动摘要、验证证据、未验证/失败项、遗留问题、工作区及 Git 状态、建议下一步。关闭详情返回原看板／任务聊天，不跳成新的主页面。允许展示文件名及数量摘要，不打开文件、不显示源码/diff。

每条验证显示命令/检查项、运行环境、时间、退出状态和脱敏输出摘要；明确“未执行”和“执行失败”。没有验证证据时不显示全绿通过。构建、跨平台、真实 Agent 和 Actions 各自单列，不能互相代替。

按钮是“接受此结果”和“继续修改”。接受绑定结果版本，独立记录“已验收”，不迁移专题；明确要求继续修改时建立新修订，更新执行角标，之后重新查看结果并验收。已有执行结果的任务中的普通讨论不单凭收到消息就自动启动修改。合并/推送另走对应授权；“已验收 / 未合并 / 未推送”可以同时成立。工作区归档为后续生命周期功能，依赖真实 Git 包含关系、远端与成果保留检查，不随验收自动删除。

### 5.8 配置方案

列表展示方案名、说明、主/执行角色摘要、模板版本及可用性。编辑表单先展示常用项：名称、pi、模型、实际支持的思考级别；高级区放上下文、权限及执行约束，字段随能力开放，不预先承诺自由脚本或可视化编排。

保存生成新模板版本；提示“仅影响后续新任务”。已有任务查看只读快照和覆盖记录。凭据只选服务器上已有引用，网页不回显 Key、不持久化 Key。删除被历史引用的模板保留历史快照，建议先做停用而非物理删除。

### 5.9 断线、休眠、多标签页与更新

连接状态：连接中 → 已连接 → 重连中/离线 → 需要重新认证。离线时显示最后同步时间；保留已加载内容，禁用新任务、审批、停止、模型修改等写操作。任务状态标注“最后已知”，不能显示服务器仍在执行的实时承诺。

重连使用服务实例/事件世代和游标补发，去重并按序应用；游标失效时重新读取权威快照。事件缓冲溢出不静默丢弃，转为重新同步。后台标签页恢复可见时检查快照，避免浏览器节流后继续展示过期状态。

草稿优先保存在内存；跨刷新恢复建议使用当前标签页 sessionStorage，以服务实例＋已认证身份＋projectId＋scopeType＋Conversation ID 隔离，任务范围再含 taskId。项目草稿同样必须隔离。认证退出／切身份时清除旧身份缓存与草稿；不要给新身份显示之前选中任务的内容。用户需知晓草稿在浏览器本地，默认不持久化聊天和结果；有配额／保存失败要提示。关闭／刷新前任一范围有未发送文本才提示，不只检查当前输入框；任务执行本身不阻止关页。

多标签页依靠服务器幂等和版本校验，不靠浏览器选一个“主标签页”保证正确性。客户端与服务协议不兼容时进入只读提示；有新版时用户选择刷新，不强制丢弃草稿。不启用 Service Worker 离线写入或自动缓存敏感 API。

## 6. 状态与显示规则

生产状态由服务持有；专题是独立用户分组，前端不把服务状态投影为列，也不从按钮点击或单个 pi 事件推断任务完成。原型的五态只用于演示，不证明真实业务状态映射。

| 对象 | 建议状态 | 产品表达 |
| --- | --- | --- |
| 任务 | queued / active / awaiting_review / accepted / failed / cancelling / cancelled / interrupted | 待开始 / 进行中 / 待验收 / 已验收 / 失败 / 停止中 / 已停止 / 执行中断 |
| 专题归属 | topicId | 用户分组，删除专题仅转入其他；不是执行状态 |
| 卡片角标 | 未开始 / 执行中 / 需要确认 / 执行完成可查看结果 / 执行失败 | 与专题独立，生产细状态映射另审 |
| 当前聊天范围 | project / task | 无卡片选中为项目；选中为任务；不是运行状态 |
| 范围加载 | loading / ready / unavailable | 加载中、可发送、不可用；不可用不偷偷换范围 |
| 阶段 | analysis / implementation / verification / revision | 分析 / 开发 / 验证 / 修改中 |
| 执行子任务 | queued / running / blocked / succeeded / failed / cancelled / interrupted | 独立状态；执行成功不升级为整个任务已验收 |
| 交互请求 | pending / answered / rejected / expired / superseded | 待处理 / 已回应 / 已拒绝 / 已过期 / 已失效 |
| 模型覆盖 | requested / scheduled / applied / failed | 正在请求 / 下一轮生效 / 已生效 / 设置失败 |
| 连接 | connecting / connected / reconnecting / offline / unauthenticated | 独立于任务状态 |

“等待用户输入/审批”是可叠加的阻塞原因：一项执行受阻时，其他独立执行可能仍运行。服务确认整个任务无可继续工作时才显示整体等待，不把单个子任务的阻塞覆盖全局。

服务重启后无法证明进程/锁状态时标记 interrupted 并要求核查；不自动恢复副作用操作。Agent 无运行中调用但任务还在派发、验证或等回复时，任务可以仍处于 active。

## 7. 视觉、可用性与无障碍

建议使用温和浅色底、深色正文、青绿色主操作、橙色待处理、红色失败；另提供系统/深色外观。状态同时包含文字或图标，不只靠颜色。以看板扫描、明确选中范围和右侧对话阅读为中心；卡片少用阴影，避免仪表盘式装饰。

正文建议 15–16px、充足行高；触摸按钮目标至少 44px。所有操作可键盘访问，焦点可见；卡片用可聚焦选择控件，Enter/Space 选中后明确播报任务范围，“返回项目对话”可键盘访问。选中样式不只靠颜色。抽屉/模态框限制焦点、Esc 关闭、关闭后归还触发点；关闭详情不能顺带清除任务选择。不可逆动作不绑定全局快捷键。

流式文本不逐 token 打断屏幕阅读器，阶段/错误/发送结果使用节制的 live region。支持减少动画；错误就近显示，不能只靠短暂 toast。长标题、长路径允许折行/复制，手机端不产生横向页面滚动。

首版 UI 以中文为主，内部状态与 API 字段保持稳定标识。时间展示本地时区，悬停/详情提供完整时间和时区；耗时与连接新鲜度不混用。

## 8. Web 技术与部署提案

### 建议方案

浏览器端采用 **Vue 3 + TypeScript + Vite** 单页应用，方案待确认；路由及必要状态管理从最小依赖起步，不引入另一套后端。Vue 提供组件和响应式 UI；Vite 可生成静态构建产物。这些是官方能力，适合本项目是设计判断。[Vue 官方介绍](https://vuejs.org/guide/introduction.html)、[Vite 生产构建](https://vite.dev/guide/build.html)。

替代方案是 Go 模板＋少量浏览器脚本，首屏和构建简单，但本项目的流式对话、深链接、跨面板状态与重连仍需客户端状态层；建议仅在用户希望尽量减少前端工具链时采用。两者都能保持后端全 Go；选择前不安装工具、不锁版本。

生产由同一个 Go 服务提供静态页面、业务 API 与 WebSocket，同源部署。静态产物可使用 Go embed 随二进制分发；具体打包路径需实施时定，不能直接跨目录 embed `../../apps/web/dist`。[Go embed 官方文档](https://pkg.go.dev/embed)。不需要常驻 Node 服务、SSR 或 BFF；Node 仅为候选前端开发/构建工具。开发代理仅绑定回环，远程联调另获授权。

资源建议：带内容哈希的 JS/CSS 长缓存，HTML 重新校验，业务 API/认证内容不缓存。客户端和服务传递协议版本、能力列表及构建版本。未知 API 返回 JSON 错误，不掉进 SPA HTML fallback；任务深链接正常回退到页面入口。[Vite 构建与缓存说明](https://vite.dev/guide/build.html)。

### 安全与访问方式（独立设计前置项）

- 远程开放前选择配对/认证/TLS 方案；优先评估同源、服务端会话、HttpOnly Cookie、CSRF 令牌与 Origin 校验。不是本轮擅自确定实现或开启监听。
- 同机回环也需防恶意网页发起请求和 DNS rebinding，不能用“只监听 localhost”替代 Host/Origin 与身份校验。
- WebSocket 握手校验身份和 Origin，避免把长期凭据放 URL；会话过期/撤销需让事件连接同步失效。VPN 本身不替代应用认证。
- Agent/用户文本作为不可信内容；Markdown 禁止原始 HTML，链接过滤协议并明确外链，限制远程图片，防止日志或模型输出形成 XSS。正式部署配置 CSP、防嵌入和资源访问边界。
- 密钥不进前端包、浏览器存储、日志或诊断导出；浏览器接收脱敏产品事件，不透传原始 stderr。

上述为上线门槛提案，具体会话时长、配对凭证及证书部署另行审核。

## 9. 与 Go 服务的协议边界

先定义三端共享产品协议，再连接现有 pirpc；不将 pi 原始 JSON 直接作为公共 API。建议最小资源为：Project、Topic（功能专题，含其他保底归属）、Conversation（项目／任务两种范围）、Message、ProfileVersion、Task、TaskConfigSnapshot、AgentRun、Execution、Workspace、InteractionRequest、Verification、ResultRevision、OperationReceipt。

消息必须携带确认后的 conversationId 与 scopeType/projectId，task 范围包含 taskId；服务核验范围归属、权限和可用性，并路由到该 Conversation 绑定的独立 pi 会话，不以“当前 UI 选中”作为服务端路由依据。Conversation 的范围和会话归属不因用户点卡片改变。消息、流式内容、审批、操作回执带其不可变关联标识；快速切换产生的迟到记录只能更新原范围。具体运行实例、启动与恢复协议在后续 Go 业务规格中确定。

命令通过 HTTP 提交，返回可查询操作记录；流式变化经 WebSocket 传递。所有有副作用的命令带幂等键、目标 ID、预期版本；审批额外绑定动作摘要与有效期。错误区分字段无效、凭据缺失、工作区冲突、能力不支持、审批失效、服务离线和操作结果未知。

事件建议包含服务实例/世代、事件 ID/游标、对象 ID/版本、时间与产品载荷。具体游标作用域和持久化方案必须随存储设计确认；前端不得用本地时间排序判定因果。先取带水位的快照、再补水位之后事件，避免读取/订阅间丢事件。

浏览器 WebSocket API 不自带接收背压；服务/客户端都需要有界缓冲和聚合，不让大量工具输出拖垮页面。[MDN WebSocket](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket)。首版建议仅保留可见文本与有限事件窗口，旧消息分页；达到上限时重新同步或提示截断，不能静默伪造完整记录。

## 10. 开发分期与依赖

| 批次 | 交付 | 依赖与通过条件 |
| --- | --- | --- |
| W0：交互原型 | 已实现专题增删／其他、任务五态角标、双范围聊天及异步隔离 | 15 项状态测试＋44 项 Chromium 检查；仅本地模拟，真实 pi 未接入 |
| W1：协议与界面工程 | 先核对专题归属与任务状态分离、选择、两范围消息／草稿与异步隔离；经选型确认后创建 Web 工程、组件、路由 | 合成数据有持续标识；A→B切换／迟到消息／草稿与键盘、响应式检查通过 |
| W2：项目与单任务真实闭环 | Go 持久化项目／任务 Conversation 和配置，项目协调与任务主／执行工具桥、worktree 锁、真实结果 | 隔离假进程优先；真实模型前说明并获相应许可 |
| W3：可长期使用 | 幂等/审批/模型边界、重启中断处理、重连、多标签页、验收修订 | 可靠性场景与可信执行边界通过，不用 UI 掩盖缺失能力 |
| W4：远程与发布 | 认证/TLS/配对、生产静态分发、浏览器矩阵、更新/兼容策略 | 方案审核后才能远程监听；真实发布另获授权 |

W1 可先做模拟 UI，不以 W2 未完成阻塞视觉讨论；W2 从贯穿前后端的一条最小链路开始，而非先建设通用工作流引擎。认证威胁边界在 W1 设计、在任何真实写操作暴露前实现；W4 是远程部署验收，并非此前业务可以无认证上线。

Web 优先作为完整体验的验证入口，三端共用任务协议。PC/Android 继续推进各自工程与原生体验，不能把响应式 Web 验收替代三平台 Leaf 或 Android 验收。

## 11. 验收场景

1. 空项目、无基线、pi 缺失、凭据无效均能解释并保留输入，不偷偷修复环境。
2. 新建时选择整套方案，任务快照可查看；后改模板不改变该任务。
3. 重复点击及提交响应丢失只产生一个任务；能查询未知结果。
4. 主 Agent 实际派发执行，看板卡片／任务详情显示隔离 worktree 与服务端写入占用；两个写入者不能同时进入同一工作区。
5. 运行中补充需求明确进入下一轮，当前请求继续；发送失败保留文本，中文输入法不误提交。
6. 修改模型时当前调用持续；下一轮实际调用与展示一致，模板未改变；不可用模型给出原因。
7. 两个设备同时审批只执行一次；过期/变更目标不能复用授权；拒绝不会擅自取消全部任务。
8. 关闭网页不中断执行；重连、游标过期、事件重复/乱序及页面休眠均可恢复到权威状态。
9. 服务重启后不能证明的执行标记中断；不自动重放 Git/工具副作用命令。
10. 停止时先显示停止中，残留进程不能被标成全部停止或释放写入锁。
11. Agent 结束但验证未跑时仍显示未验证；接受结果、提交、合并、推送有独立记录。
12. 360px 手机、平板、桌面及键盘操作可完成核心流程，长文本/路径不破坏布局。
13. 不可信 Markdown/链接、错误 Origin、无效/撤销会话和 CSRF 请求被正确处理。
14. 协议不兼容有明确提示，刷新不丢待处理状态；日志/前端包/浏览器存储无秘密。
15. 项目默认首屏为看板＋项目对话；选中 A／B 后右侧显示该任务且卡片选中标识一致；返回项目不换看板或执行状态。
16. 项目、A、B 三份不同草稿和滚动位置分别恢复；发给 A 后切 B，A 的成功／失败不清掉 B 草稿。
17. A 的历史请求或流式回复晚于 B 的加载完成，不能在 B 的标题下显示 A 内容；切卡片本身不启动／取消进程。
18. 所有消息携带不可变范围；伪造 projectId/taskId、不可用或越权会话被服务拒绝，不能默认发到项目。
19. 卡片移列、筛选隐藏或归档不改变已选聊天；任务失效明确禁发，恢复项目需显式操作，深链接保留错误提示。
20. 审批／停止／模型操作请求后切卡片仍指向原对象；已接受操作不能被重复提交或移到新范围。
21. 看板列是可增删的功能专题；任务右上角有五种状态角标，状态变化不搬列。执行完成可查看结果不自动代表用户验收，Git 状态独立。
22. 消息未读、项目汇总和任务原始聊天可区分；不自动把所有历史注入新任务，不用选择卡片就清空全部未读。
23. 同一任务卡片可键盘选择；显式返回项目、窄屏看板／聊天切换、详情打开关闭均保持范围一致。
24. 刷新／离开前其他隐藏范围的未发送草稿也有提示；身份退出清除该身份的草稿和内容缓存。
25. 空看板仍可显示项目对话／创建未开始任务；讨论和创建任务不偷偷执行，无 Git 基线时真实开始按钮明确受限。
26. 添加专题创建空列；空白／过长／同名名称失败时保留输入，不多创建列；专题名与任务／聊天文本含 HTML 时只显示文本。
27. 删除有任务专题将全部任务原子移到其他；ID、五种状态、选中任务、对话、草稿和结果都保持，不取消执行；取消删除不改任何数据。
28. 保底其他不能删除；空专题可删；新任务默认其他，已删除专题的创建表单不会导致任务丢失。
29. 许多专题、长标题与角标不造成页面整体横向溢出；桌面只滚动看板，手机按专题查看，选中范围不暗变。

浏览器建议覆盖 Chromium（Chrome/Edge）、Firefox、Safari/WebKit 及移动 Chrome/Safari，具体最低版本随实际选型和用户设备确认。静态原型、前端组件测试、真实浏览器测试、Go 协议/故障测试、真实 pi、原生端、Actions 分别记录。

## 12. 现有原型状态与下一步决策

[当前交互原型](../../design/web-prototype.html) 使用无依赖 HTML 和同目录纯状态脚本，浏览器直接打开。已实现专题增删、其他收纳、任务创建、五种角标、右侧项目／任务独立历史和草稿，以及捕获 Conversation 的模拟接受／回复。宽屏看板居左、聊天居右，小屏切换两视图。[桌面截图](../../design/web-desktop.png)、[手机截图](../../design/web-mobile.png) 和 [实际验证](../../development/web-kanban-prototype-verification.md) 属于本批。

[限定原型实施计划](../plans/2026-10-11-web-kanban-prototype.md) 已按用户“继续开发”推进。项目与每张任务卡片分别拥有独立模拟会话标识；没有启动真实 CLI、连接 Go、持久化或执行 Git。[历史 20 项检查](../../development/web-design-verification.md) 与其中的旧截图仅代表此前聊天居中提案，不替代新测试。

确认看板交互后再分批决定 Vue 3 + TypeScript + Vite 或 Go 模板、认证／持久化及真实执行边界。浏览器只是 UI，后端全 Go 继续有效；本修订没有批准前端依赖、生产业务或模型额度调用。

后续仍保留**团队协作**与**通用可配置编排引擎**两个方向；本轮建议优先级继续低于个人 Web 完整闭环，未因此增加多人账号或通用流程编辑器。
