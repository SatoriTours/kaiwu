# Go 管理 pi RPC：进程与通信基础设计

状态：**书面规格已获用户确认：用户在审核请求后回复“继续”。** 已编写 [实施计划](../plans/2026-10-11-go-pi-rpc.md)，待审核计划及执行方式；尚未开始编码或运行验收，不提交或推送。

## 1. 意图、决定与成功标准

开悟先做好个人开发工作台中的 pi 主 Agent＋执行 Agent 闭环。本批次先建立可靠的进程和通信底座：Go 能启动受控子进程、确认 RPC 通信就绪、关联命令响应、独立接收事件，并准确报告故障和回收结果。

已确认：

- 开悟自有后端全部使用 Go；不新增 TypeScript/JavaScript 扩展、Node/Bun SDK 宿主或其他语言后端模块。
- pi 本身是第三方 CLI，其 Node 运行时不是开悟自有后端代码；本批次不重写或安装 pi。
- 新模块归属 `server/internal/pirpc/`，替代此前候选位置 `internal/agent/pi/`；不预建通用 Agent 适配框架。
- PC Nim＋Leaf 与 Android Kotlin/KMP/Compose 的首版方向不变。
- 先用隔离的 Go 假进程验证，真实 pi 启动和模型调用另行许可。

方案取舍：Go 直管 RPC 链路最短；TypeScript SDK 宿主与纯 Go 后端要求冲突，排除；终端屏幕抓取不适合作为可靠协议，排除。未来编排工具桥优先研究 Go MCP 服务与 pi 内置 MCP 对接，本批次不实现。

成功标准是进程/协议基础可被确定性测试，**不是**真实 Agent 已联调、开发任务可自动完成或双端可用。

## 2. 实现范围与排除项

包含：受控启动、协议握手、LF JSONL、并发请求关联、原始事件 FIFO、持续消费 stderr、有界资源、取消语义、故障退出与直接子进程回收。

不包含：

- HTTP 任务路由、WebSocket、客户端、数据库、持久化、事件补发或服务重启恢复。
- 配置模板/快照、主执行编排、worktree 管理、工具权限桥、MCP 服务或人工审批 UI。
- 完整的 pi 业务 SDK、任务完成状态机、模型切换生效边界、会话恢复。
- 自动重启、自动重发命令、安装或升级第三方软件。
- 跨平台后代进程树取消或安全沙箱。

现有 `kaiwu-server` 仍只有健康接口，配置和启动流程不自动运行 pi；健康响应不能变成 Agent 就绪承诺。

## 3. 兼容依据与模块职责

本批次以观察到的 pi **1.0.4 RPC schema** 为有限协议基线。依据为安装产物的 RPC 文档、`rpc-types.d.ts`、`rpc-mode.js`、`jsonl.js`，见 [接入研究](../../research/agent-integration.md)。这是有限兼容目标，不是已完成真实联调或永久兼容全部 pi 版本。

`get_state` 没有协议版本协商字段；不能靠一次响应声称已识别安装版本。测试固定合成 schema；后续真实接入需独立核对安装身份和启动配置。

拟在同一 Go 包内按职责分文件，不新增 Go module 或第三方依赖：

| 单元 | 职责 |
| --- | --- |
| protocol | 出入站 envelope、参数验证、响应关联字段、类型化错误 |
| jsonl | 只按 LF 处理字节流、UTF-8/JSON 校验和单记录限制 |
| process | 明确的执行参数、管道所有权、唯一 Wait、stderr 消费和退出检测 |
| client | 启动握手、请求容量、串行写入、ID registry、取消和统一终态 |
| events | 按记录顺序保存原始事件，按数量和字节限制 FIFO |
| Go 测试与合成样例 | 单元测试及受控假子进程，不使用个人配置或真实日志 |

依赖仍为标准库；保留既有 Go 1.25.0 语言基线和 chi 版本。实际文件粒度在实施计划中确定，不先创建空包。

## 4. Go 调用边界与生命周期

本文规定操作语义；准确类型/签名在实施计划中据此固定，不能改变语义：

| 操作 | 契约 |
| --- | --- |
| Start | 接收服务/任务所有者的 lifetime context 和显式启动参数；握手成功后返回可用 Client，失败负责清理已取得资源 |
| Call | 发出普通 RPC 命令并等待对应响应；Go 生成 ID，允许并发调用，实际 stdin 写入串行 |
| NextEvent | 带独立调用 context，取下一条原始事件；不是广播，不拥有进程生命周期 |
| Close | 所有者明确停止进程；幂等、并发安全，不以调用方等待超时中断已启动的清理 |
| Wait | 等待进程回收与 I/O worker 收尾，提供终态原因、可获取的退出码和是否强杀；不是 Agent 运行结束等待器 |

状态仅为 transport 的 starting → ready → stopping → stopped；故障原因单独保留，不映射为产品任务成功/失败。禁止重启同一 Client，恢复需未来任务层明确处理。

### 启动参数与就绪

- 显式指定绝对可执行路径、参数数组、绝对工作目录和非 nil 环境变量列表；空列表表示空环境，不隐式继承 `os.Environ()`。拒绝非法参数和负值限额；Options 中零值限额使用本文默认值，正值覆盖默认值。
- 不拼 shell 命令，不搜索 PATH，不默认发现个人 pi、凭据、扩展或项目配置。
- 本批次只启动 Go 测试助手。真实 pi 命令、环境白名单、隔离 Agent 目录、扩展/工具限制和会话目录在后续真实启动批次设计。
- 先开启 stdout/stderr 消费及退出监视，再发送带 ID 的 `get_state`。等待匹配的成功响应，验证 data 为对象、sessionId 非空、isStreaming/isCompacting 为布尔值、pendingMessageCount 为非负整数。
- 握手期间也接收事件。Start 在取得资源前检查生命周期取消；握手后还检查是否已检测到退出或故障。启动失败、坏响应、超时或生命周期取消均不得返回可用 Client；返回前执行清理，清理失败明确报告。不保证返回后进程永远存活，后续退出必须由终态通知可见。
- 就绪只证明 RPC 可交换状态，不证明凭据、模型、工具或产品任务已准备完毕；不用固定 sleep 或“进程未退出”充当握手。

生命周期 context 必须归服务/任务所有者，**不能传入某次 HTTP 请求或客户端连接的 context**。当前包不绑定 HTTP；后续集成须由稳定的服务内部所有者消费事件。

## 5. JSONL、响应与事件

### 分帧与基本校验

- stdin 输出一个 UTF-8 JSON 对象加 LF。stdout 只按字节 LF 分帧，可去掉 LF 前的单个 CR；U+2028/U+2029、中文和分片 UTF-8 不构成边界。
- 支持跨读取的半行、一次读取多行以及超过 Scanner 默认 64KiB 的合法记录；收集未完记录时即执行限制，不能等整条巨型记录读完才检查。
- EOF 时若剩余字节形成完整合法 JSON 对象，交付最后记录，兼容 pi 的无最终 LF 行为；若为截断 UTF-8/JSON，报告协议故障。
- 空记录、非 JSON、非法 UTF-8、非对象、缺失/无效 type、stdout 文本污染或记录超限是 transport 故障，不默默忽略。新增的合法事件 type/字段保留为原始数据，不为每种模型消息建立业务类型。

### 普通命令响应

- Call 的 type 为有界普通命令名称，参数为有界 JSON 对象，默认空对象；拒绝参数覆盖 id/type。命令名称限定小写字母开头、其后为小写字母/数字/下划线，最多 64 字节。
- ID 由 Client 单调生成，生命周期内不复用；先登记请求，再排队写入，避免快速响应丢失。
- 只有 `type: response` 走响应关联。其 id/command 必须为有效字符串，success 必须显式为 bool；失败响应的 error 必须是字符串。
- 对有效 pending ID，command 必须匹配原命令；不匹配或损坏的 envelope 是协议故障。普通 success:false 是远端命令拒绝，不终止整个 Client，Call 返回该响应和可识别的拒绝错误。
- 已超时/取消后的迟到响应及重复、未知 ID 响应忽略并计数，不能匹配新命令，也不能伪装成事件。缺 ID 的 response（如上游 parse 错误）是不可关联的协议故障。
- `prompt` 的 started/queued/handled 原样返回；不等待 `agent_end` 或 `agent_settled`，不据此声明任务成功。禁止 transport 自动重发。

### 事件与扩展 UI

- 其他合法对象原样入 FIFO，保持 stdout 观察顺序；响应不进入事件队列。原始内容只在内部 Go API 提供，不直接固定为公共客户端协议。
- 用 NextEvent 拉取，而不是让 stdout reader 同步调用 UI 回调或等待浏览器。FIFO 以数量与原始字节双重限制；取出时释放预算。
- NextEvent 供一个逻辑消费者使用；它不是多订阅广播。等待被取消只结束该次读取，不停止进程。
- 进程终态后，已入队事件仍可顺序取完；队列空后才返回终态错误或正常 EOF。队列不需要一个永久阻塞的分发 goroutine。
- `extension_ui_request` 保留为事件。`extension_ui_response` 使用上游 ID 且不返回普通 response，不能通过普通 Call 发送；本批次拒绝该 type，不实现回应、不自动确认或批准。真实启用此类能力之前必须另行实现 UI/授权流程。

## 6. 有界资源、超时与取消

本批次默认值如下；Options 中零值使用默认值、正值覆盖、负值拒绝，测试使用较小正值限额，不增加环境配置项：

| 资源/等待 | 默认值与定义 |
| --- | --- |
| 单 JSONL 记录 | 4MiB UTF-8 原始载荷，不含终止 LF/可选 CR；入站和出站均检查 |
| 并发 Call | 32 个，含排队、写入、等待响应，容量直到调用返回才释放；满时立即拒绝新调用 |
| 待写载荷 | 16MiB，包含排队和当前写入的记录；写完/撤销即释放，不长期保留参数 |
| 事件 FIFO | 最多 128 条且原始载荷总量最多 16MiB；先触及哪个上限就执行哪个 |
| stderr 诊断尾部 | 64KiB 固定上限，持续读取并覆盖旧内容，不因没人看日志停止消费 |
| 启动握手 | 8s |
| Call 总等待 | 默认 30s，自入场开始；更早的调用 context 截止优先，可显式配置等待限额 |
| 单记录写入期限 | 自开始写入起总计 2s；不是无限延长的进度计时器。超过时破坏管道并停止故障 transport，不能卡住写入 worker |
| 优雅停止 | 关闭 stdin 后最多 5s，超时 Kill 直接子进程 |
| 退出后输出排空 | 最多 1s；未到 EOF 则显式报告 drain 超时并关闭自有读端 |

字节预算约束 Client 持有的原始载荷，不等于整个 Go 堆的绝对大小；结构分配、当前解析缓冲、并发响应以及调用方保存的数据另有有界开销或由调用方负责。不能以无界 channel/切片替代上述限额。

取消语义：

1. 参数非法或未入场即取消：不写入，不产生远端操作。
2. 已排队且能确认尚未开始写：撤销记录，移除登记并释放容量，报告未发送；同时释放排队记录的引用，不能积累无限取消标记或保留其载荷。
3. 正在写或已经写完后等待超时/取消：结束该次 Call，报告远端执行结果未知，不自动 abort、重发或重启。registry 释放后，迟到响应不改变已返回结果。
4. 传输故障（写停滞、读故障、坏协议、事件溢出）与普通调用超时不同：会使整个 Client 停止，并使尚未回答的请求失败。首个 transport 故障原因保留，不能被清理错误掩盖。
5. 明确停止当前模型运行属于未来控制层的显式 `abort` 命令；它与 Close 不同，也不证明所有后代进程已退出。

事件溢出选择**显式失败并回收直接子进程**，不丢弃事件冒充完整流、不无限占内存，也不让慢消费者永远阻塞 stdout。溢出记录未交付的事实由终态原因可见，已入队记录仍可读取。磁盘缓冲/持久化留待后续；后续客户端断线必须由服务内部消费与订阅隔离，不能等价于 FIFO 无人消费。

## 7. 退出、管道与诊断

- 进程退出有唯一 Wait 路径；所有自有管道和 worker 有明确收尾。采用自管 `os.Pipe` 或经测试证明等价的所有权方案，不能在 Wait 中提前关闭尚未读完的 stdout 而丢失最后响应。
- 意外退出时禁止新 Call；在有界时间内处理 stdout 已写出的完整记录，随后使未回答的请求失败。已经收到成功 response 不因随后退出改写为“未接受”，但也不代表任务成功。
- stdout 提前 EOF、stdin/stderr 不可恢复 I/O 故障均可观测；不能把仍活着却失去协议的进程留作健康 Client。
- Close 或生命周期取消时，先停止接收新 Call、解除 pending 等待、撤销未开始写的记录，再关闭 stdin；继续消费 stdout/stderr，等待退出，超过优雅期限则 Kill，最后确认直接子进程被回收。
- 已开始的清理不依赖调用 Close 的请求 context；该 context 只限制调用者等待，清理继续且由 Wait 查看最终结果。
- 强制 Kill、输出排空超时、Kill/Wait/句柄关闭失败均保留为可检查结果；不能在未确认回收时报告已停止。正常显式 Close 可正常结束，意外退出即便退出码为 0 也不是任务成功。
- 不承诺终止 pi 启动的 bash、工具或 detached 后代。异常持有输出 fd 时只关闭本包拥有的读端并报错，进程树管理必须在真实执行闭环前另行设计。

普通日志只允许生命周期、PID、命令名称、统计与固定错误类别；不记录命令参数、消息正文、环境、凭据、原始 stdout/stderr 或会话内容。错误的默认字符串同样不能拼入远端 error 或 stderr。

受限 stderr 尾部及原始错误响应只通过显式内部诊断/响应访问提供；不自动落盘或透传 HTTP。测试使用合成秘密标记验证边界，不使用真实凭据。

## 8. 假进程与验收

实现采用 TDD。测试助手由 Go 编写，可使用同一测试二进制的明确 helper 模式；传入绝对路径、临时工作目录和显式最小环境。测试不得启动 pi/Node、加载个人扩展、访问模型或依赖固定端口/机器私有路径。所有测试均有外层截止和 cleanup 兜底。

必须覆盖：

1. 分片/多记录、CRLF、中文、跨读取 UTF-8、U+2028/U+2029、超过 64KiB 的合法消息。
2. 无最终 LF 的完整末记录；截断 JSON/UTF-8、空行、非对象、缺 type、stdout 污染和记录超限。
3. 请求 ID 唯一；先登记后写；并发写不交错；乱序响应正确关联；响应间穿插未知合法事件。
4. 远端 success:false、匹配 ID 的错误 command、缺 ID/缺 success、未知/重复/迟到 ID，以及扩展 UI ID 不误关联普通请求。
5. started/queued/handled 不等待 settled；agent_end/agent_settled 只是事件，不产生产品任务验收结果。
6. 真实管道下的握手成功、坏状态、失败/超时、启动即退出与提前生命周期取消。
7. 并发/待写容量限制、取消排队与发送后结果未知；取消 Call/NextEvent 后进程仍能接受其他命令；无自动重发。
8. stderr 连续大量输出但不阻塞协议，尾部有界；默认日志和错误字符串不包含合成秘密标记。
9. 事件数量/字节超限不阻塞、不无界增长、显式失败；终态后仍可读已入队事件。
10. 子进程不读取 stdin 时的写停滞、stdin broken pipe、stdout 提前 EOF、意外退出，以及退出前最后 response/event 的排空。
11. Close 幂等/并发、优雅退出、忽略 stdin EOF 后强杀、等待 Close 的 context 取消但清理继续；确认直接子进程回收、worker 结束且无残留测试进程。
12. 输出排空截止的受控故障测试；如测试助手产生后代，仅测试夹具负责明确回收，不将其回收算成本包进程树能力。
13. 显式启动环境与工作目录、无隐式个人环境继承、无 shell/PATH 查找及原始数据的独立所有权。

执行时分别记录 `GOTOOLCHAIN=local GOFLAGS=-mod=readonly go test ./...`、`go test -race ./...`、`go vet ./...`、格式、依赖校验、构建和关键并发/退出重复测试。每项实际输出独立记录；本机仍为非稳定 Go 工具链，不冒充稳定 Go 1.25、其他系统、真实 pi、UI 或 Actions 验收。文档-only 阶段不报告这些测试已执行。
