# 任务卡片开始开发：双入口与执行生命周期

状态：用户已审核本方案并回复“ok”，授权按方案开发。实现进度和实际证据另行记录，不以设计当成已实现。

## 目标与范围

卡片创建后可以先讨论，明确开始时才启动开发。卡片按钮和任务聊天指令触发同一个 Go 操作，以卡片需求和该任务的讨论为输入，在独立 Git 工作区内运行 pi 执行 Agent。选择卡片、切换聊天和创建卡片不隐式开始。

本批包含显式启动、实际 pi 执行、状态／输出回传、失败和重启恢复。项目主 Agent 自主批量派发、通用工作流、团队协作、自动提交／合并／推送不在本批；PC 三平台和 Android 目标保留。

## 交互

- 每张未开始的卡片底部有“开始开发”按钮，选中卡片的聊天也有同一入口。改造现有整体 button 卡片，避免嵌套 button，并保留键盘选择能力。
- 卡片上的开始选中该任务并显示其聊天，然后发起启动；普通点击继续只切换聊天。
- 任务聊天发送独立一句“开始开发”触发同一 `start_task`，保存原用户指令和回执。允许首尾空白和末尾标点；“先不要开始开发”等包含词语的句子不误触发。
- 未选卡片的项目聊天发送“开始开发”提示先选择任务，不任意启动第一张卡片或全部任务。
- 普通消息继续讨论，首次启动带入本卡片需求及其讨论，受现有文本限制，不混入其他卡片历史。
- 启动立即显示提交状态并防止连点。服务端同时防止跨标签页或新 operationId 重复启动同一卡片。
- 缺 pi／模型／容量时显示具体原因并保留输入；不改变为“执行中”或虚构执行。卡片按钮保留，以便用户知道启动入口与阻塞原因。
- 任务执行中禁用再次开始；失败可查看原因并明确重试；中断提供恢复；轮次结束提供查看结果。专题归属不随执行状态变化。

## 启动命令与配置

沿用已认证、同源的 `/api/commands`、操作标识和回执查询，新增 `start_task`，包含 projectId/taskId，聊天入口另携带原指令。服务端校验目标归属、配置、忙碌状态及工作区占用。

启动使用卡片已经冻结的配置；未配置且从未调用过模型的卡片，首次开始时从服务配置冻结有效快照。已有模型上下文的卡片不悄悄换模型。升级前创建、尚无模型的卡片不用删除重建；实际执行仍需服务先配置有效 pi／provider／model。

SQLite 保存 executionId、taskId、卡片会话 ID、配置快照、工作区、Git 基线、阶段、起止时间、错误和结果。开始指令、执行记录与幂等回执先持久化，再由服务调度；调度前重启标中断，不偷偷补发。HTTP 接受、工作区准备、CLI 握手、prompt 接受、轮次结束分别记录。

## 工作区

每张任务首次执行分配独立 worktree 和任务分支，同一工作区只允许一个执行者。路径由服务生成，浏览器不能指定任意执行工作区。

- 有提交：固定启动时的 SHA，创建任务 worktree。主目录存在未提交 tracked 修改时提示确认基线，不偷偷忽略或自动提交这些修改。
- 空仓库：使用 orphan worktree，不为了建工作区自动创建提交。当前本机 Git 2.55.0 已在临时仓库验证可行，主仓库仍无提交。
- 无提交但已有文件：只复制 Git 列出的未忽略普通项目文件作为输入，不跟随越界符号链接，不复制 `.git`、开悟私有数据或凭据。无法安全准备时停止并说明，保留主目录。
- Git 不支持 orphan 时明确阻塞，不自动升级或提交。
- 重试／恢复复用记录的工作区，校验根目录、分支和执行归属；不重置、删除或覆盖已有任务结果。

服务不自动 commit、merge、push、删除分支或清理 worktree。结果留在任务工作区，集成操作需后续明确指示。

## 执行 Agent 与能力变化

Go 新增任务执行控制，复用 `pirpc` 和现有会话管理器。项目 pi 作为主 Agent 保持只读；每张卡片仍是一个独立 pi，会话 ID 和模型上下文保持连续。任务开始前可只读讨论，明确开始后该卡片会话进入开发模式，cwd 为任务 worktree、会话目录仍私有。

如果卡片已启动只读 CLI，须先确认它空闲，可靠保存并停止旧进程，再以原 session 文件、原会话 ID 和开发工具配置恢复；旧进程未回收、会话损坏或工作区身份不匹配时拒绝切换，不另起第二个上下文冒充继续。尚未启动的卡片直接在 worktree 中首次启动。任务在途 prompt 未结束时不能切换模式。

执行输出保存在该卡片原对话，项目主 Agent 和其他卡片历史继续隔离。已开始任务的后续沟通仍使用该卡片的执行会话；模型可以继续开发，不在每轮结束后偷偷换回另一个只读会话。

执行者具备读、写、编辑与运行验证命令的能力，使用冻结配置，禁用个人扩展、个人 MCP 和自动上下文发现。输入明确只改任务工作区并汇报实际修改／测试，不执行未授权提交、合并、推送等操作。

这涉及从只读升级为可以运行代码。worktree 是 Git 隔离，不是系统沙箱；不能声称 cwd 或提示词能拦截任意越界。实施计划须落实工具授权与子进程所有权，明确可验证的能力边界。通用 Go MCP 编排桥不因显式按钮而自动纳入，不新增 TypeScript 扩展或宿主。

现有 RPC 只回收直接子进程；开启执行前须补齐进程组／子命令停止测试。先验证当前 Linux 服务的执行，未验证的后端平台明确拒绝执行；这不取消多端目标。所有 pi 实例共享既有上限 8，不为执行另开一个隐蔽容量池。

## 结果与恢复

开始后进入执行中；异常保留错误、输出和工作区。客户端断线、切卡片不停止执行。未知投递不自动重发。

`agent_settled` 只说明本轮结束：展示摘要、实际观察到的修改／验证记录，任务进入“需要确认”。无测试记录明确显示“未执行验证”，不标通过、不自动验收。

重启将未完执行标为中断。用户明确恢复时核对旧进程清理、原工作区和会话文件，恢复会话与重发指令分开。丢失／损坏时停止并说明，不悄悄换新上下文。

## 验收

临时 Git 仓库和隔离假 pi 验证：双入口同一操作、目标归属、否定句／项目聊天不误触发、无模型、重复点击／跨标签页／回执丢失不重复派发、有提交／空仓库 worktree、主目录保护、配置冻结、同一卡片模式切换保留原上下文／单实例、跨卡片历史隔离、真正产生固定文件的工具执行、失败／中断／明确恢复、子进程回收、未经验证不显示成功。
