# 任务结果、效果预览与完成反馈

状态：2026-10-16 提供设计与原型，2026-10-17 用户明确要求“开始修改”；已按本设计实施真实 HTTP 预览与成果确认流程。[实施计划](../plans/2026-10-17-task-result-preview.md)记录本批具体接口／进程／能力路径约束，[验证记录](../../development/web-task-result-preview-verification.md)记录实际验收与上线状态。

## 问题与目标

目前“确认结果”只调用 `confirm_result`，把最新已结束轮次对应任务标记为完成；点击后确认区域消失。它不打开预览、不启动服务、不提交或合并。用户因此无法判断刚才发生了什么，也缺少验收实际效果的入口。

调整为：开发结束 → 查看效果／运行结果 → 继续修改或确认完成 → 明确显示完成反馈及后续入口。保留专题看板、右侧原任务聊天及独立 worktree，不引入源码浏览、编辑器或 IDE。

[可点击原型](../../design/task-result-preview.html) 包含网页、命令行、暂无预览，以及预览停止／启动失败场景。数据和服务启动均为模拟。

## 首屏与操作

任务状态显示“待验收”，含义仍为原有 `needs_confirmation`，不直接把 Agent 结束当作用户验收。顶部成果区展示一两句本轮成果、可查看的效果和验证情况；详细方案与工具记录继续折叠。

| 场景 | 主要入口 | 配套入口与反馈 |
| --- | --- | --- |
| 网页／HTTP 应用 | 查看效果 | 继续修改、验证情况、确认完成 |
| CLI／库／配置／无界面任务 | 查看运行结果 | 使用说明、测试摘要与实际输出；不强造网页预览 |
| 缺少可用效果或运行结果 | 查看成果说明 | 明示“暂无可预览效果”；补充预览／补充验证的请求须由用户发出 |
| 预览已停止／启动失败 | 启动预览／重试 | 展示具体原因，保留成果；启动完成且检查可访问后才显示可用 |
| 已确认完成 | 查看效果／运行结果 | 持续显示“你已确认本轮结果”；可合并到主分支或继续修改 |

将“确认结果”改名为“确认完成”，旁边说明“看过效果并认可后，将任务标记为完成”。默认以查看效果为主操作；查看后可提升确认完成的视觉权重，但不以是否点过链接作为验收证据，也不强制所有任务必须有预览才能确认。验证缺失／失败保持可见，不在确认时改写为通过。

确认后留在当前任务，持续显示成功反馈及卡片“已完成”角标。Git 状态继续独立显示待提交／未合并／已合并；需要集成时打开现有具体合并审核，沿用审核后显式提交与普通合并，不增加推送。没有可合并改动时依实际 Git 状态显示原因。继续修改聚焦输入框，不擅自生成或发送需求；用户发送新要求后才产生新一轮结果，历史验收保留。

## 预览呈现与真实性

桌面点击“查看效果”后，主内容区从看板切到所选任务的效果预览，顶部提供返回看板、刷新及第几轮成果标识；右侧聊天常驻，便于边看边提修改。手机进入独立效果视图，提供明显的返回任务对话入口，避免把网页挤进狭窄聊天气泡。不新增源码或 diff 页面。

效果必须与任务、执行工作区及成果轮次绑定。若后续修改已改变工作区，则旧轮次只显示其成果记录，并提示“当前预览来自最新工作区，不能复现历史效果”。不承诺存档每轮可运行环境。预览可用性与验收、Git 合并状态是三个独立维度。

正式接入需要 Go 保存并检查预览进程、目标、健康状态及归属；Agent 报告的 URL 只是候选，不能直接当作已运行或用户浏览器可达。服务器的 `localhost` 不能直接成为远程客户端预览地址。建议经现有认证入口受控访问任务预览，不新增任意 URL 代理或自动暴露新的局域网端口；具体代理、网页兼容性、启动命令授权与资源限额在实现前明确。不向 iframe 直接注入任意 Agent HTML，预览应用须与工作台凭据隔离；不适合嵌入的应用用受控独立窗口打开。

预览生命周期归服务器管理，关闭页面／切卡片不停止预览。显示实际运行／停止／失败状态，提供显式停止入口；确认完成不自动停止，便于回看。资源限额和退出／归档处理必须明确，不默认无限常驻，也不因已验收删除 worktree。无新用户动作不自动调用模型补充预览，不把日志文本伪装成真实网页效果。

## 实现边界与验收标准

建议分两步：先改进成果入口、完成命名与持久反馈，展示已有真实输出及缺少预览的状态；随后接入 Go 受控预览服务。不能仅改按钮文字就声称已支持效果预览。原型仅用于设计评审；2026-10-17 正式实现已接入 Go 管理的真实任务预览，并在隔离项目运行浏览器验证。

- 网页任务能从最新成果打开真实工作区效果；浏览器端确实可达才显示可用。
- 非网页任务能查看使用说明和本轮实际输出；无依据明确标记缺失。
- 预览启动失败、端口冲突、进程退出、手机返回均有明确反馈；不会误改任务验收状态。
- 确认完成成功后留在原任务，完成角标及文字反馈持久可见，刷新仍成立；重复点击、离线和过期轮次沿用现有幂等与精确版本校验。
- 确认不提交／合并；后续合并仍使用现有审核流程及实际 Git 状态。
- 提出修改继续原 pi 会话和 worktree，生成新轮次；旧验收记录与效果来源不混淆。
- 用户数据、登录凭据和工作台 API 不暴露给任务预览；预览归属、资源和进程生命周期有实际验证。
