# 轻量任务卡片设计提案

状态：2026-11-06 用户要求仔细设计、持续优化后，明确“改代码”，已批准第二轮设计实施；不含提交或部署。历史静态稿检查保留，正式实现进度见本批验证记录。

## 意图与范围

针对用户截图中的任务卡片，解决编号抢占首行、标题层级弱、底部操作平均分散和看板多层灰色容器的问题。沿用现有 Vue 看板、功能专题及独立聊天抽屉，不改会话、任务、Git 或交付状态机。保留用户已要求提亮的冷灰深色与灰绿浅色，不改回近黑。

设计稿：[静态对照](../../design/task-card-refinement-v1.html)。本稿为无外部资源的本地 HTML，所有状态是合成数据、所有业务按钮仅提示。不是生产界面或功能验收。

## 方案比较与推荐

1. **只调色与缩间距**：改动最少，但编号优先、操作分散和重复身份仍在，不推荐。
2. **轻量卡片（第二轮后获批实施）**：保留看板，重排卡片信息，弱化专题容器；标题／状态、可选辅助行、编号／操作三个层次。
3. **紧凑任务列表**：密度更高，但弱化功能专题的空间分组，超出本次卡片问题，不采用。

用户在第二轮精修后明确要求改代码，本轮按轻量卡片方案实施。

## 信息结构

```text
添加数据库的能力，我要能       未开始
输入我的每段话

KW-0752a8                      ▷  ⋯
```

- 使用完整现有 task.title，不按逗号自动拆标题，不调用模型改写。
- 不增加默认需求摘要：已有标题往往就是需求，再加摘要会重复且增高。
- 首行 grid：标题 minmax(0, 1fr)，右侧状态 auto，12px 间距、顶端对齐。
- 标题 14px / 22px、字重 500，使用 text-wrap: balance 平衡多行长度，减少末行孤字。最多三行，不为短标题固定占两行；原文通过打开任务对话可读，桌面 title 仅作补充，不作为手机唯一阅读途径。
- 右上角保留现有 taskState() 的真实文案，11px / 22px、不缩成无文字图标。多项待回答仍保留数量。
- 新回复只在标题尾部放一个小蓝点，并提供无障碍名称，不用圆点承载“新回复”文字。
- 底栏左侧为原有 KW 编号，11px；不截得更短，也不因此新增复制或业务 API。
- 底栏右侧为连续操作组：审核合并（原条件满足时）／状态相关主动作／更多。去除 justify-content: space-between 对每个按钮的均分。
- 删除每卡重复的 π 头像和 pi 标签；本期只接入 pi，确切执行端／模型仍在任务聊天既有信息中查看，不删除配置。
- 普通 Git 状态与编号同处底栏，用中性分隔点区分，空间不足时在左侧自然换行，不挤操作。子 Agent、待回答和交付信息才放独立辅助行；没有内容不占高。

| 项 | 桌面 | 手机 |
| --- | --- | --- |
| 卡片内边距 | 14px | 14px |
| 圆角／间隔 | 7px／10px | 7px／10px |
| 图标／点击范围 | 16px／28px | 16px／44px |
| 标题 | 14px / 22px | 14px / 22px |
| 标题与底栏间距 | 12px | 8px |
| 简单卡片目标高度 | 约 92–114px | 约 104–126px |

高度是内容驱动的参考，不是固定高度承诺；三行标题／辅助信息可继续增长，不做整卡裁切。长英文路径允许 anywhere 换行。320／360／390px 验证状态、标题和三个操作均不横溢。

根据用户对正式实现截图的最新反馈，保留原有专题列整块背景（theme-inset：暗色#333a43／浅色#f3f5f3），不可透明化；保留列圆角及整列高度。各列中性一致，不按列序配状态颜色。早前静态稿的列透底是历史方案，不再作为正式列背景依据。正式产品保留现有列宽上限350px、最小248px、独立纵向滚动／横向看板、手机单专题选择，不因设计稿三列排布改变业务布局。建议列间距16px，卡片10px间距。第二轮静态稿手机已改为真实单专题选择的展示模式，原纵向样本集仅作为首轮快照保留。

保留48px全站顶栏、现有新建入口、聊天抽屉，不借本次重做全站。空专题用一条轻量空态而非虚线大框，不新增与原列头重复的新建按钮。

## 状态与主动作

所有文案和动作继续以现有 taskState／actionLabel 和权限门禁为准。下表表示视觉，不新增业务状态。

| 状态 | 视觉 | 主动作 |
| --- | --- | --- |
| 未开始 | 中性文字，无底框 | 播放图标，悬停“开始开发” |
| 执行中／启动中 | 小蓝点＋文字；只对既有活动标志做适度动画 | 原执行中／启动中禁用态，不变成暂停按钮 |
| 待你处理 | 小琥珀点＋真实交互文案／数量 | 原处理入口，不触发新开发 |
| 待验收 | 琥珀提示＋“待验收” | 查看结果；完成仍在更多菜单显式确认 |
| 已完成 | 克制的绿色提示，不把整卡变绿 | 查看结果；不推断已合并／已部署 |
| 已中断／待继续 | 中性状态＋文字 | 继续开发，沿用原上下文自动接回 |
| 执行失败 | 小红点＋文字 | 原重试入口，详情在聊天内读 |

“执行中”不再与“需要用户注意”共用琥珀色。待处理卡片不整面染黄。多项回答、送达待核查、自动交付暂停等真实文案不能被一个笼统状态覆盖。

## 复杂卡片与溢出策略

- 标题三行后省略；点击打开完整任务。不使用断词改写或自动摘要。
- 状态自然宽度，不与编号／交付徽标挤在首行。原交互文案约束之外的长状态允许换行，状态列最大104px，保留完整可读文案；实现需针对“回答发送中”“送达待核查”回归。
- 底栏左侧依次为编号、Git 状态；辅助行放子 Agent／待回答、交付，间隔12px，可折为多行。链接默认无下划线，hover／focus有明确反馈，不使用无限徽标。
- 真实 Git 状态独立保留，例如“已完成／待提交”“执行失败／已合并”可并存；主状态不代替 Git 状态。
- 子 Agent 汇总仍可点击原详情，不伪造派发或自动执行能力。需要注意的子 Agent 状态使用既有提示。
- 自动交付活动时沿用现有主动作／合并入口隐藏门禁；本稿并排状态样本不代表启用 worker。
- 更多菜单保持显式完成与原键盘导航；不增加删除、归档、自动提交等未批准功能。

## 交互与可访问性

- 标题／卡片非操作区打开原任务对话；选中不等于启动，关抽屉不停止任务。
- 图标常驻，手机不依赖 hover 才能找到按钮。桌面 tooltip 和 aria-label 使用同一真实动作名称。
- 操作按钮不冒泡打开聊天；不把含按钮的整张 article 再包成按钮，不在父角色 button 中嵌套可交互控件。
- 使用原生标题按钮和独立操作按钮提供键盘入口；无障碍名称保留完整标题及真实任务状态。
- 编号不是按钮，不为实现“复制”额外增加一个 Tab 停靠。
- 空闲卡片不添加动画；尊重 prefers-reduced-motion。离线、启动进行中、等待用户等所有禁用规则保持原样。
- 菜单不被列容器裁切；缩放200%、键盘焦点、短视口要单独检查。
