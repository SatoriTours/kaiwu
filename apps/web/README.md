# Web 主工作台

正式实现使用 Vue 3＋TypeScript＋Vite；生产页面由 Go 同源提供，自有后端全部 Go。

看板由可增删的功能专题列和任务卡片组成。当前本地改版将常驻聊天替换为默认收起的右侧独立抽屉：点击卡片打开任务对话，点击「项目对话」打开项目范围；桌面宽720px覆盖全宽看板，手机全屏。关闭按钮、遮罩或Esc仅隐藏聊天，不停止后台任务／会话或清空当前页面草稿；结果页也可返回任务对话。各范围保留独立 pi 会话、历史和草稿。每次打开、刷新或切回时定位最新消息；手动上翻不被新回复拉回，回到底部后继续跟随。删除专题只把任务转入“其他”，保留对话；手机按专题显示单列。[抽屉验证与未部署边界](../../docs/development/web-chat-drawer-verification.md)。

主题默认实时跟随系统，可在登录页／顶栏手选浅色或深色，浏览器记住偏好；选择「跟随系统」移除覆盖。主题与抽屉已获用户提交代码授权，按既有测试／部署流水线交付；实际入口以完整运行修订号为准。

## 项目菜单与顶栏

左侧点击文件夹与当前项目名切换项目；菜单内提供「Git 设置」「刷新 Git 状态」「添加项目」，当前项目有勾选标记。顶栏右侧统一放默认模型、连接状态与退出。长项目名在顶栏省略、菜单内完整显示；可用方向键、Home／End、Enter／Space、Esc 和 Tab 操作。重选当前项目保留任务与草稿，切换项目不停止后台任务。[本批验证与截图](../../docs/development/web-project-menu-verification.md)。

## 本机运行

从仓库根目录执行（已有 Node、npm、Go）：

```bash
npm --prefix apps/web ci
npm --prefix apps/web run build
export KAIWU_DATA_DIR="$PWD/.kaiwu"
# 从密码管理器生成至少 32 字节的随机令牌，在下面和登录页使用同一个值。
export KAIWU_WEB_TOKEN='替换为你自己的随机访问令牌'
GOTOOLCHAIN=local go -C server run ./cmd/kaiwu-server
```

打开 http://127.0.0.1:7331 ，用令牌登录，填写服务器上项目目录的绝对路径。保存时自动创建不存在的目录，普通目录自动初始化 Git，无需勾选；已有仓库直接登记，已有文件保留，不创建提交。旧页面只提交名称和路径也能初始化。

登录状态保留 30 天；刷新页面、重新打开浏览器及服务重启均可恢复。主动退出、到期或更换服务访问令牌后需要重新登录。浏览器保存 HttpOnly／SameSite Strict 的随机登录 Cookie，SQLite 仅保存凭证散列、访问令牌散列与到期时间，不保存原始访问令牌。旧版内存会话升级后需重新登录一次。

“Git 远程地址”可留空，已有仓库留空会沿用其配置；填写 HTTPS／SSH 地址仅配置 `origin`，不会克隆、联网、提交或推送，也不会覆盖已有的不同 `origin`。不要在地址内嵌入密码或令牌。初始化及数据库保存是两个步骤；若保存失败，已经创建的目录／仓库会保留，可检查后重试，服务不自动删除文件。

构建会把静态资源复制到 Go embed 目录，修改前端后须重新构建并重启 Go。

不设置 KAIWU_WEB_TOKEN 时维持仅健康检查的基础服务。服务自动从 PATH 查找 pi；未找到 pi 或尚未选择模型时，看板可以使用，聊天保留输入并提示对应缺项。`.kaiwu/` 是私有持久数据，包含数据库及会话文件，已被 Git 忽略；备份需停止服务后整体复制，勿提交真实记录或凭据。

推荐直接在 Web 选择模型：

1. 顶栏“默认模型”打开真实 pi 可用列表，可按提供商筛选、搜索；保存后用于之后创建的项目对话和任务，重启后仍保留。
2. 现有未启动的项目／任务，在聊天输入框下方点击“pi · 选择模型”补选。卡片缺模型时点击“开始开发”也会打开选择窗口；保存后再次明确开始，草稿保留。
3. 模型窗口说明沿用服务器 pi 已有登录；服务器仅复制所选提供商凭据及模型定义到隔离会话，不加载个人扩展、不下发密钥、不回写个人配置。未登录时先在服务器 pi 中登录，再“重新检测”。检测不发送模型请求。

默认设置不追溯已有会话；聊天“选择会话模型”现在可为已启动会话明确选择“下一轮使用此模型”，显示待生效状态，不中断当前轮、不回写项目模板。服务在下一轮边界可靠回收空闲实例，以原 session 和新配置恢复，并核对实际模型；失败不偷偷使用旧模型。仅隔离假 pi 验证，真实跨 provider／OAuth 仍待授权联调。已保存的 Web 默认优先于启动环境默认。也可在启动 Go 前指定环境默认：

```bash
export KAIWU_PI_PROGRAM='/绝对路径/pi'
export KAIWU_PI_PROVIDER='你的提供商'
export KAIWU_PI_MODEL='该提供商的模型ID'
export KAIWU_PI_THINKING='medium'
```

`KAIWU_PI_PROGRAM` 可省略；以服务进程的 PATH 为准，nvm 安装需让服务 PATH 包含相应 Node／pi 目录。手工路径配置不会被自动结果覆盖。默认环境模式仍只传提供商 API Key；Web 选择模式额外使用服务器 pi 登录的隔离副本，源目录为 `PI_CODING_AGENT_DIR` 或 `~/.pi/agent`。只支持静态配置或已传递环境变量，拒绝 `!command` 凭据。支持传递的 Key 变量见 [config.go](../../server/internal/pimodel/config.go)。实际模型调用、OAuth 续期与执行任务仍待联调，本批仅验证真实模型元数据。

## 当前能力边界

- 项目／任务 Agent 回复沿用系统界面语言，当前为简体中文；规则覆盖普通对话、过程更新、结果摘要和报告文字，启动及恢复均追加，历史英文消息保留，代码和协议值不翻译。这是提示约束，真实模型输出仍待验证。[本批验证](../../docs/development/web-reply-language-verification.md)。
- SQLite 保存项目、专题、任务、消息及幂等回执；刷新恢复权威数据。未发送草稿仅保留在当前页面内，退出清空；刷新前提示未发草稿。不再保存旧阅读位置，重新进入对话时显示最新消息。
- 首次发送才启动独立 pi，切卡片或浏览器断开不停止后台会话；每会话一条在途消息，最多 8 个驻留实例。
- 服务重启／进程异常后，新消息或继续开发自动接回原会话；严格检查原会话文件和 ID，不自动重发结果未知消息。丢失／损坏的已用会话拒绝恢复，不悄悄新建上下文。
- 项目及未启动任务使用 `read,grep,find,ls`，pi 在会话私有目录启动。选择卡片不控制进程；点击卡片／对话“开始开发”，或任务聊天单独发送“开始开发”（可带末尾句号／感叹号），才进入开发模式；项目聊天会提示先选择任务，否定句不会触发。
- 开发模式限 Linux：原卡片 pi 保留 session ID／文件及上下文，在任务独立 worktree 使用 `read,write,edit,bash,grep,find,ls`。旧进程和消费协程可靠结束后才切换，最多 8 个会话共享容量。只读工具和 worktree 均不是系统沙箱；这是受信任的本机 CLI，可运行代码和命令。
- 有提交的项目从自动识别并冻结的主分支 SHA 创建任务分支，已跟踪的未提交改动会阻塞首次启动；空仓库使用支持 `--orphan` 的 Git，复制未忽略的普通初始文件（包括暂存文件），排除常见凭据／私有数据目录。工作区保存于 `.kaiwu/worktrees/<任务 ID>/tree`，按任务校验并复用；任务轮次结束不自动提交或合并。
- 任务执行阶段、工具记录和结果摘要已保存；轮次结束为“需要确认”，没有验证命令时显示“未执行验证”。已有结果可在原任务继续沟通；执行失败可明确重试。服务重启只恢复身份／工作区，不重发旧指令。部分准备失败会保留目录并提示检查，不擅自覆盖。任务 OS 锁与持久进程归属在强杀后防止双写；旧组仍有活动进程或启动归属未知时拒绝再次执行，不按保存的 PID 杀进程。确定未派发的首次指令标记“未发送”，恢复原身份后可重新明确开始，不会自动补发。
- 通用 Go 编排桥、自动派发、通用工具审批与真实模型完整验收尚未实现；五态角标与聊天运行状态分开，不把模型回复结束当任务完成。
- 默认本机回环 HTTP；用户现已要求并启用指定私网 IP 的局域网访问，仍必须令牌 Cookie 登录。公网／TLS／设备配对需后续设计；PC 三平台和 Android 目标保留。

## 自动交付设置（当前仅开放草稿）

项目菜单打开“交付设置”，概览只保留用途、交付方式和三个入口：**目标仓库**（交到哪里）、**通过标准**（哪些检查通过才合格）、**失败处理**（最多让 AI 修几次）。不再放没有操作能力的四步流程图；详细配置用分步普通表单，高级参数默认折叠。不向普通用户展示 JSON、内部仓库编号或凭据引用名，也不在浏览器填写 Token。

**当前版本暂未开放自动交付，启用按钮禁用**。只能保存未启用、未授权的配置草稿；草稿通过原 WebSocket／Go 接口真实保存到 SQLite，失败保留输入。已有启用策略只读保护，不能因保存草稿而静默关闭或改写授权。保留项目实际主分支，不强制改成 main。服务器尚未提供仓库／workflow 元数据发现接口时显示未配置，不虚构列表或凭据就绪。预检只读取已保存配置，不检查尚未保存的输入，也不会提交／推送。任务和主分支推送均可能触发已有部署／发包，人工效果验收与技术检查仍独立。

卡片／聊天区分功能结果、Git 和交付阶段；已启用任务通过本地及任务 CI 后按配置等待“效果验收通过”，随后服务串行集成与主 CI。没有人工验收的周期明确显示“未人工验收”，不自动把旧任务标 completed。支持暂停后原会话修改、候选重验、下一轮模型及只读技术记录；活动周期不显示旧手动合并／确认入口。

**上述是开发中的界面与隔离流程，不可据此启用真实自动上传。** 独立后端审查仍有远程凭据／冻结定义、恢复与主线隔离阻塞；详细状态及续接见[验证记录](../../docs/development/web-automated-delivery-verification.md)与[未关闭问题](../../docs/development/web-automated-delivery-review-resolution.md)。此前界面已部署到 7331，但真实交付 worker 未装配；本次精简改版的实现、验收及发布状态见[改版验证记录](../../docs/development/web-delivery-settings-redesign.md)。不把临时 bare／假 Actions 结果当作真实验收。

## 卡片合并到主分支

卡片底部显示实际 Git 状态，任务聊天进展卡底部可展开主分支、简短 SHA、检查时间及阻塞原因。活动项目每 3 秒检查，进入项目／重新可见／执行结束立即检查，也可在项目菜单中选择「刷新 Git 状态」。执行角标与 Git 状态分别显示；执行结束不自动表示已经合并。

点击卡片或任务聊天顶部的合并图标，或在任务聊天单独发送“合并到主分支”“提交并合并到主分支”（可带“请”和末尾句号／感叹号），打开审核框。审核目标、SHA、待提交文件路径、说明与身份后确认：有修改则“提交并合并”，已有提交则“合并到主分支”。缺少本地身份时明确使用 `Kaiwu <kaiwu@localhost>`。项目菜单「Git 设置」提供可选主分支覆盖及提交身份；添加项目无需填分支。

合并由服务器持有，关闭窗口／切卡片／断线不取消；再次点原卡片合并图标可查看操作。失败后可重新检查，不自动重试有副作用的 Git；重启核查已记录 SHA，不重放。提交成功但合并失败会保留任务提交。普通合并快进优先，分叉时无冲突则生成合并提交；保留分支、worktree 和原 pi 会话，不推送／清理。

脏主目录、目标未 checkout、未完成 Git 操作、敏感路径（包括任务新引入历史中后来删除的文件）、外部 filter／merge driver／分支 mergeOptions、子模块或特殊文件会阻止一键集成；代码成果保留，按原因先在 Git 中处理。外部 squash／cherry-pick 不能凭相同内容代替完整提交祖先关系；合并后新增修改／提交恢复待处理。当前不验证代码语义或功能测试，也不能保证普通 pi bash 经过此审核入口。[本批验证与限制](../../docs/development/web-task-merge-verification.md)。

## 查看成果与效果

开发结束后显示“待验收”。先点“查看效果”：网页任务可运行真实任务预览；无网页配置的任务展示原回复、成果与实际工具输出。认可后点“确认完成”，任务持续显示已完成，仍可查看效果、继续修改或按现有审核合并到主分支。确认不改写验证证据、不自动提交或合并。

网页任务在其独立工作区提供 `kaiwu-preview.json`，例如（实际脚本必须支持对应参数）：

```json
{"version":1,"command":["python3","server.py","--host","127.0.0.1","--port","{port}"],"path":"/hello"}
```

页面展示实际命令，用户点“启动预览”才执行。端口由 Go 分配，进程仅允许监听指定 IPv4 回环地址；核对实际进程组与 HTTP 就绪后，经原 7331 认证入口的任务能力路径访问。展示配置的 SHA256 与启动请求绑定，配置改变要求刷新核对；没有配置时“补充预览说明”仅预填原任务草稿，由用户决定发送。

当前限 Linux、最多 4 个预览、10 秒就绪超时、64 KiB 诊断。仅 GET/HEAD；应用登录、WebSocket/HMR、跨源资源与根绝对资源可能不兼容。关闭页面、切卡片和确认完成不会停止服务；继续开发、合并或 Go 服务退出时安全停止，原会话与工作区保留。效果链接最长 30 分钟，失效时点“刷新状态”；不自动续签或恢复旧服务。iframe 为 opaque sandbox，任务网页不能读工作台 Cookie 或父页面；这不代表任务代码经过操作系统沙箱。

## 开发与验证

聊天消息和结果摘要支持 Markdown 标题、粗体、列表、任务清单、引用、链接、表格和代码块；代码块可复制，常用语言高亮，未知语言保留为纯文本。工具调用仍折叠展示，JSON 自动缩进。输入框右上角的眼睛图标切换草稿预览，铅笔图标返回编辑；输入框 Enter 发送，Shift + Enter 换行，中文输入法选字回车不发送；保留 Ctrl／⌘ + Enter 快捷键，草稿预览也支持 Enter 发送，服务器保存和发送的仍是原文。切换会话回到编辑模式，各范围草稿保持隔离。

正式页面使用双向 `/api/socket`：登录后的命令、模型查询、Git 预检／合并／操作回执和状态同步均通过 WebSocket。HTTP 保留登录、退出、首次认证快照及异常断线后的轻量会话检查；旧 `/api/events` 和 HTTP 业务路由保持兼容。后续文本追加发送字段增量，有界窗口可按 revision 补发；窗口缺口或服务重启回退权威快照，大快照使用 256 KiB UTF-8 分块，完整收到才替换状态。断线不自动重发消息、不停止 Agent，仍查询原操作回执。页面隐藏、切项目或断开停止当前 Git 只读订阅；正在执行的任务和合并由服务器持有。

聊天中的连续过程更新合并为一条“执行进展”，默认显示最新简述及更新数，长回复显示摘要，展开后保留全部原文；摘要保留 Markdown 段落及列表，相关 HTTP/HTTPS 链接单列完整地址，可点击在新标签页打开。优先使用已有结构化报告摘要，没有报告时提取回复前几个段落，不额外调用模型。不同用户轮次及最终回复独立展示。聊天顶部优先显示任务要求、最近回复／AI 摘要、执行记录数量及实际待提交文件；方案、成果、验证、记录可展开，历史轮次可选择。无报告和手机默认收起详情，结果确认在首屏，中断时直接发送或继续开发，保留聊天阅读空间。AI 在原调用末尾上报结构化 JSON，不额外调用模型总结；原始回复保留，长回复和过程可展开，无效报告回退原文并提示。成果是 AI 报告，验证另列实际工具返回／失败和缺少依据，不把命令完成当作功能验证通过。仅最新已结束轮次可“确认结果”；已完成结果即使会话断开或恢复失败仍可确认，旧版结果用精确版本校验。中断任务明确显示“已中断”，直接发送新消息或点继续开发图标时自动接回原会话／工作区；不再先点恢复，不重发或自动完成上次指令。确认结果不提交或合并，后续修改仍形成新轮次。项目概览统计真实任务状态。[实现与验收](../../docs/development/web-progress-socket-verification.md)。
